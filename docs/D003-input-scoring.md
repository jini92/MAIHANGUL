# D003 · 다국어 입력·채점 설계

상태: **Draft / 기술 검증 전** · 기준일: 2026-09-30

대상: R07~R09, R17 · [A001](A001-PRD.md) · [UX](D002-learning-game-ux.md) · [검증](T001-validation-plan.md)

## 1. 불변 조건과 선행 실험

조합 중 문자열은 화면에만 표시한다. 오답 강조·정확도·진도·제출을 발생시키지 않는다. **확정한 문자열을 사용자의 명시적 제출 한 번에만 채점**한다. React 상태가 DOM보다 늦을 수 있으므로 제출 시점 스냅샷과 현재 questionEpoch를 함께 검증한다.

`compositionstart/update/end`, `beforeinput/input`, `keydown/keyup`, `blur/focus`, `isComposing`, `inputType`, 실제 DOM 값의 순서를 MH-001/002에서 기록한다. `compositionend.data`가 최종 전체 문자열이라고 가정하지 않는다. composition 이벤트만으로 모든 Telex/VNI 변환을 관찰할 수 있다고 가정하지 않는다. MH-007의 구체 확정 처리 알고리즘은 실제 로그를 근거로 확정한다.

**단순한 MVP 제출 정책:** 입력란의 Enter는 앱 제출을 하지 않는다. IME 중에는 기본 확정을 방해하지 않고, 일반 Enter의 줄바꿈/암묵적 form 제출은 막는다. 제출은 “입력 확인” 버튼 클릭 또는 Tab으로 버튼에 이동한 뒤 새 Enter/Space로 한다. 이 선택은 조합 확정 키와 제출을 분리한다. 입력란 Enter 단축 제출은 향후 개선 후보이며 이번 MVP 필수가 아니다.

관련 표준은 일반 이벤트 모델의 근거일 뿐 특정 OS·브라우저의 동작 증거가 아니다. [W3C UI Events, 작업 중 초안](https://w3c.github.io/uievents/#events-compositionevents), [Microsoft Windows Vietnamese IME](https://learn.microsoft.com/en-us/globalization/input/vietnamese-ime)

## 2. 상태와 전이 계약

| 상태 | 이벤트/행동 | 결과 |
|---|---|---|
| stable | compositionstart | composing, 조합 전 확정값 보관, 타이머 시작 후보 |
| composing | compositionupdate/input | 표시값만 갱신; 제출 요청 폐기, 채점 0회 |
| composing | compositionend | settling; DOM 전체 값·뒤따르는 input과 대조; 자동 제출 없음 |
| settling | 지원 환경에서 확인된 최종 이벤트 묶음 종료 | 확정 스냅샷 갱신 후 stable; 이전 제출 요청 재실행 금지 |
| stable | 일반 input/삭제/선택 교체 | 최신 DOM 값 확정; 아직 채점하지 않음 |
| stable | 유효한 버튼 제출 | epoch·시도 일치 확인, 즉시 submitted 잠금, 채점 1회 |
| submitted | 더블클릭/Enter 반복/늦은 input | 점수·진도 추가 없음; 명시적 재시도/다음만 허용 |
| 모든 상태 | 중단/문제 전환 | 현재 epoch 무효화; 새 세션으로 이벤트·예약 콜백 유입 금지 |

최종 `input`이 없는 환경의 DOM 읽기 시점, end 이후 input이 있는 환경의 안정화는 선행 실험 결정 사항이다. 고정 지연(예: 100ms), deprecated `keyCode===229`, 단일 `isComposing` 플래그만을 종료 증거로 사용하지 않는다. 확인되지 않은 이벤트 순서에서는 제출을 보류하고 다시 입력/지원 환경 안내를 제공한다. 지원 범위를 늘리기 위해 중간 값을 채점하는 완화는 하지 않는다.

## 3. 경계 사례

- **Enter:** 입력란 keydown을 form 제출로 연결하지 않는다. key repeat는 제출 행동이 아니다. 버튼에서도 composing/settling/잠금이면 제출하지 않는다. 조합 종료를 유발한 포커스 이동/클릭을 같은 제출로 재사용하지 않고, 안정화 후 새 행동을 요구한다.
- **취소:** Escape·IME 후보 취소·조합 삭제는 OS가 만든 최종 DOM 값으로 동기화한다. 빈 end.data를 곧바로 전체 입력 삭제로 해석하지 않는다. 앱 중단 확인은 IME가 처리하는 Escape와 분리한다.
- **Backspace:** 조합 중이면 OS 편집, 확정 후면 일반 문자열 편집이다. 지운 글자/키 수를 오답 횟수로 누적하지 않는다.
- **포커스 이동:** 조합 중 Tab/마우스 이동으로 확정 또는 취소될 수 있음을 실험한다. 마지막 확정값만 보관하고 이동 자체로 제출하지 않는다. 해석·UI 언어 변경을 위해 입력 노드를 재마운트하지 않는다.
- **UI 언어 변경:** 안정화 후 문구만 바꾸고 같은 attempt/DOM 입력을 유지한다. 조합 중 요청은 지연한다.
- **연습 언어/문제 전환:** 미완료 취소를 확인한 후 epoch 증가·타이머/오디오/콜백 폐기·입력 초기화. 이전 element의 늦은 end/input이 새 문제를 덮지 못하게 한다.
- **재시도:** 같은 콘텐츠라도 새 attemptId와 빈 입력이다. 첫 결과를 덮어쓰지 않는다. 새 시도를 명시한 뒤에만 잠금 해제한다.
- **중단:** 같은 탭은 마지막 확정 문자열로 재개하고 interrupted=true. 새로고침은 미완료 문제 처음부터, 완료 기록 중복 없음. 조합 중 값은 저장하지 않는다.
- **제출 전 빈 값:** 정규화 결과가 비면 입력 안내만 표시하고 시도/오답/속도 기록을 만들지 않는다. 문제 건너뛰기는 별도 incomplete이며 정확도·의미 분모에서 제외한다.

## 4. 다국어 비교 정책 `strict-nfc-v1`

| 항목 | MVP 정책 |
|---|---|
| 정규화 | 정답과 확정 입력 모두 NFC 후 앞뒤 U+0020 SPACE만 제거 |
| 내부 공백 | 개수 보존. 연속 공백·누락 공백은 다름 |
| 다른 공백 | 탭·줄바꿈·NBSP를 일반 공백으로 바꾸지 않음; 입력 오류/차이 안내 |
| 구두점 | 보존·비교. 마침표 생략, 전각/반각 임의 통합 없음 |
| 영어 대소문자 | 구별. 자동 소문자화 없음 |
| 베트남어 | Telex/VNI가 만든 최종 텍스트를 비교. 성조/모음 부호 제거·ASCII 변환 없음 |
| 한글 | NFC로 정규 동등성 비교. 호환 자모를 NFKC로 임의 변환하지 않음 |
| 대체 정답 | MVP는 변형별 정답 문자열 하나. 유사 표현을 자동 정답 처리하지 않음 |
| 붙여넣기/드롭 | 연습 허용, 해당 시도 assisted=true를 끝까지 유지; 속도 비교에서 제외 |
| 자동 완성/대체 | 가능한 범위에서 끄고 관찰된 replacement 입력은 assisted로 표시. 미탐지 가능성 때문에 부정행위 탐지라 주장하지 않음 |

화면에는 공백/구두점/대소문자 규칙을 도움말로 제공한다. 모든 문제에 같은 정책을 적용하여 문항별 숨은 예외를 만들지 않는다. 조합 중 텍스트를 정규화하여 다시 input.value에 쓰지 않는다. [Unicode NFC 규정](https://unicode.org/reports/tr15/)

동등 사례: `chào`와 `cha\u0300o`는 NFC 후 같다. `chao`는 다르다. `가`와 `\u1100\u1161`은 NFC 후 같지만 호환 자모 `ㄱㅏ`는 같은 답으로 추측하지 않는다. 문서의 예시 문자열은 입력 기술 fixture이며 교육·번역 검수 완료 문항이 아니다.

## 5. 계산식 `scoring-v1`

문자 단위는 NFC 후 **확장 자소 군집(grapheme cluster)**이다. 한글 완성 음절/부호 결합 문자를 사람이 보는 문자 단위로 센다. 지원 브라우저의 `Intl.Segmenter` 동작을 MH-002/008에서 확인하고, 미지원이면 잘못된 UTF-16 길이로 대체하지 않는다. [Intl.Segmenter 참고](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Segmenter)

정답 군집열 T의 길이 n, 입력 군집열 U의 길이 m, 군집 단위 Levenshtein 거리 d(삽입·삭제·교체 각 1)로 정의한다. 정답은 검증된 비어 있지 않은 문구다.

- 정확한 정답 여부: 정규화된 전체 문자열 T == U.
- **최종 문자열 정확도(%) = 100 × max(0, 1 − d / max(n,m))**. 키 입력 정확도나 수정 전 오류율이 아니다.
- **입력 속도(CPM) = m × 60 / t**. 공백·구두점을 포함한 제출 문자/분이다. 정확도와 나란히 표시한다. WPM이나 한글 타수와 동일시하지 않는다.
- t: 최초 편집 행동부터 유효 제출까지 초 단위. compositionstart/beforeinput을 우선하고 실제 이벤트 누락 시 최초 input을 사용했다는 측정 경로를 기록한다. 문제 읽기 대기 시간은 제외, 입력 중 생각·수정 시간은 포함한다.
- t≤0이면 속도 `null`, t<1초이면 너무 짧음 표시와 비교 제외. 붙여넣기·명시 중단·탭 숨김·학습 영역 밖 포커스 이탈 뒤 재개·알 수 없는 입력 방식도 비교 제외다. 입력란에서 같은 학습 화면의 제출 버튼으로 이동하는 정상 제출은 중단이 아니며 속도를 유지한다. 중단 시간을 추정해서 빼지 않는다.
- 화면 정확도는 소수점 1자리, CPM 정수 반올림. 저장에는 원값·산식 버전을 남긴다. 반올림 100%여도 문자열이 다르면 정답은 false다.
- 의미 이해: 의미 과제가 있는 완료 문항의 **첫 선택 정답 수 / 첫 선택 제출 수**. 힌트 노출/무힌트는 별도 분모로 표시하며 재시도를 최초 정답으로 바꾸지 않는다. 의미 없는 자모 과제·건너뜀은 분모에서 제외한다. 무힌트 복습은 준비 화면에서 문항 최초 렌더 전에 숨김 시작을 고른 시도만 해당한다. 같은 복습 방문의 해당 문항 해석 노출은 토글/즉시 재시작으로 초기화하지 않는다. 과거 학습 노출 자체가 없었다는 뜻은 아니다.

| 정답 / 제출 | n,m,d,t | 정확도 | CPM | 의미 |
|---|---|---|---|---|
| `한글` / `한굴` | 2,2,1,4초 | 50.0% | 30 | 별도 선택 결과 |
| `물을 주세요.` / 동일 | 7,7,0,14초 | 100.0% | 30 | 물 선택 정답, 해석 노출이면 도움 있음 |
| `xin chào` / `xin chao` | 8,8,1,16초 | 87.5% | 30 | 성조 차이는 오답 |
| `cat` / `cats` | 3,4,1,8초 | 75.0% | 30 | 삽입 오류 1 |
| `한글` / 빈 값 | 제출 차단 | 기록 없음 | 기록 없음 | 의미 단계로 자동 이동 없음 |

예를 들어 의미 첫 선택 4문항 중 도움 있음 2/3, 도움 없음 1/1이면 **도움 있음 66.7%, 도움 없음 100% (각 표본 수 표시)**다. 타자 100%가 의미 정답을 보장하지 않는다. 작은 수치로 학습 효과를 단정하지 않는다.

## 6. 비교·기록 정책

비교 그룹 = 연습 언어 + 입력 방식(한글 두벌식/Telex/VNI/영문/unknown) + PC/기기 범주 + OS/브라우저 계열 + 콘텐츠 ID/버전 + scoringVersion + 도움/중단 여부. unknown은 개인 관찰값만 보여주고 비교 집계하지 않는다. 첫 시도와 재시도도 분리한다. MVP에는 공개 순위·언어 간 순위·경쟁 점수가 없다.

원시 입력과 이벤트 로그는 개발용 선행 실험에서 **정해진 fixture만** 기록한다. 평상시 제품은 집계 결과만 로컬 저장하며 입력 원문을 저장/전송하지 않는다. 상세 저장 계약은 D001이다.

## 7. 검증 경계

MH-001/002: 실제 Windows 이벤트·문자·브라우저 로그로 설계 가정 확인 → MH-007/008: 구현·순수 계산/합성 이벤트 검사 → MH-016: 통합 UI에서 실제 OS 입력기 재검증.

합성 composition 이벤트, Playwright fill, DOM 문자열 삽입은 OS 조합·후보창·키 확정 검증이 아니다. 실제 환경 근거 없는 MH-001/002/016은 완료 처리하지 않는다. 실행하지 않은 항목은 T001에서 미실행으로 유지한다.

## 8. 베트남어 입력 시뮬레이션

현재 문항의 검토된 단어에 한해 Telex/VNI의 키 순서와 학습용 중간 문자열을 계산한다. 목표를 NFC로 정규화하고 기본 문자·모음 모양·단어 끝 성조를 보존한다. 미지원 단어나 기호에는 추측한 입력법을 제공하지 않는다. 근거·예시와 구현 검사는 [I008](I008-vietnamese-simulation.md)을 따른다.

시연은 별도 화면 상태다. 실제 입력란에 값을 쓰거나 composition/input 이벤트를 발생시키지 않는다. 시연의 시간·키 개수는 채점 입력이 아니다. 시연을 연 현재 문제의 직접 입력은 `assisted=true`로 처리하고 속도 비교에서 제외하며 정확도는 실제 제출값으로 계산한다. 닫기·재입력으로 도움 사용을 지우지 않는다. 다음 문제나 명시적인 문제 재시작은 새 범위다. 의미 과제의 해석 도움 기록은 기존 별도 계약을 유지한다.

실제 입력 방식 설정은 사용자가 PC 환경을 보고 선택한 값이다. 시연에서 Telex/VNI를 바꿔도 그 설정을 변경하거나 입력기가 설치됐다고 판단하지 않는다. 학습용 중간 프레임이 모든 입력기 설정의 실제 편집 과정을 재현한다고 보장하지 않는다.
