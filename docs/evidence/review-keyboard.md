# 자판 FE 독립 검수

검수일: 2026-09-30 · 담당: 구현에 참여하지 않은 `keyboard_review` 에이전트

## 범위와 결과

`CLAUDE.md`, `AGENTS.md`, `frontend-design`, `karpathy-guidelines`, [디자인 정본](../../design.md), [I005](../I005-keyboard-design.md)를 기준으로 검토했다. 기존 구현은 `.local/keyboard-design-before/src/`와 대조했다. 제품 코드는 수정하지 않았다.

정적 코드 검수에서 확정된 P1/P2 결함은 발견하지 못했다. 이 결론은 실제 Windows IME, 화면 읽기 도구, 원어민 검수 또는 학습 효과의 합격을 의미하지 않는다. 실제 브라우저 확인과 전체 테스트·빌드 결과는 I005의 통합 검증 기록을 따른다.

## 확인한 항목

| 항목 | 확인 근거 |
|---|---|
| 자판 배열 | `src/keyboard/layout.ts`의 5개 행, QWERTY/두벌식 병기, Tab·Caps·Shift·Enter·Space 폭과 F/J 표식 |
| 목표 안내 | 단일 자모·음절의 정적 키 순서만 계산한다. ㄱ→R, ㄴ→S, ㅏ→K, 가→R·K, 겹받침 및 복합모음 분해를 확인했다. 실제 입력값으로 진행·정오답을 추론하지 않는다. |
| Shift·손가락 | 쌍자음과 ㅒ/ㅖ에 반대손 Shift를 지정한다. R=왼손 검지, S=왼손 약지, K=오른손 중지, B=왼손 검지 매핑을 확인했다. |
| 입력 보호 | `PracticeSession.tsx`는 기존 `inputProps` 이벤트를 먼저 호출하고 키 표시만 갱신한다. scoring/input/storage 모듈의 동작을 변경하지 않는다. |
| 눌림 상태 | `usePressedKeys.ts`는 포커스된 연습 입력란의 `event.code`만 관찰한다. 키를 합성하거나 `preventDefault`를 추가하지 않는다. keyup·필드 blur·창 blur·숨김·문항/언어/phase 전환 때 상태를 지운다. |
| 다국어 | KO/EN/VI UI 문자열과 연습 언어를 분리한다. 베트남어 Telex/VNI 예시는 선택한 입력 방식에 따라 표시하며, OS 입력기를 사용하도록 설명한다. |
| 접근성 구조 | 키 그림은 입력 버튼이 아니며 각 키에 Tab 정지점을 만들지 않는다. 목표 순서와 손가락 안내를 그림 바깥의 텍스트로 제공한다. 강제 색상 모드에 목표 테두리와 눌림 outline을 구분한다. |
| 변경 범위 | 홈 장식을 키보드 미리보기로 대체하고 연습 목표/해석/입력/자판 배치를 조정했다. 문항 전환·결과·복습·중단 계약의 로직은 유지했다. |
| 검사 설계 | `tests/keyboard-guide.test.tsx`는 매핑·NFC·Shift·세 언어·IME 중 무채점·눌림 초기화·키캡 클릭 시 무입력을 검사한다. 파일 안에서 합성 DOM 검사를 실제 IME 검증과 구분한다. |

## 통합 후속 검수

- 디자인 토큰: `design.md`가 실제 구현의 녹색 테두리/짙은 녹색 눌림과 일치하며 선택 이유를 기록한 것을 확인했다.
- 작은 화면 접근: 스크롤 컨테이너 하나에 `tabIndex=0`, 세 언어의 접근 가능한 이름, `:focus-visible` outline이 추가되었다. 키캡별 Tab 정지점은 없다. 홈 미리보기에는 추가 Tab 정지점을 만들지 않는다.
- 통합 담당은 1280×720에서 목표·해석·입력·5개 자판 행이 첫 화면에 보이고, 640×900에서 전체 페이지의 가로 넘침 없이 스크롤 영역에 Tab으로 진입한다고 보고했다. 이는 통합 담당의 브라우저 확인이며 이 검수자의 별도 재현으로 기록하지 않는다.
- 키보드 가로 이동: 통합 담당이 IAB에서 기본 ArrowRight 동작으로 가로 이동이 되지 않는 현상을 관찰하여 `scrollWithKeys`가 추가되었다. 후속 소스 검수에서 직접 스크롤 영역에 발생한 이벤트, modifier 없음, 실제 가로 넘침의 세 조건을 확인했다. ArrowLeft/Right는 64px, Home/End는 양 끝으로 이동하며 범위를 제한한다. 그 네 키만 `preventDefault`한다. 다른 키와 조합키는 유지한다.
- 입력란 비간섭: 스크롤 핸들러는 연습 입력란과 형제 관계인 `.keyboard-scroll`에만 설치되어 있다. 입력란의 이벤트 전파 경로에 없고, 자식 요소 이벤트도 직접 타깃 검사로 제외한다. 홈 미리보기에는 핸들러를 설치하지 않는다. 후속 수정에서 새 P1/P2 결함을 발견하지 못했다.
- 추가된 회귀 검사는 가로 이동·경계 제한·Home/End·다른 키·Ctrl 조합·넘침이 없는 경우를 다룬다. 실제 IAB의 수정 후 가로 이동 재현은 I005 통합 기록을 따른다.

## 실행 범위

이 검수는 소스·스냅샷 diff·기존 검사 코드의 독립 검토다. 테스트와 빌드를 중복 실행하지 않았으며, 실제 OS 키보드·IME를 조작하지 않았다. 외부 게시, commit, push를 실행하지 않았다.
