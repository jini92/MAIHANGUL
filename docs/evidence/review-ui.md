- 전체 테스트·빌드 게이트는 조정자가 담당하므로 이 검수에서 중복 실행하지 않았다.

## MUST_FIX · 수정 완료

### RU-01 · 유효 콘텐츠가 일부만 있으면 추천 시작이 빈 단계로 이동

위치: `src/App.tsx:122`의 홈 시작 버튼과 `src/App.tsx:132`의 `stages.map()` 단계 버튼. 라인은 최초 재현 시점이다.

재현:

1. 계획된 최소 검수 씨앗 MH-C005·MH-C011·MH-C017만 제공하는 release 저장소 fixture를 로드한다. 각각 단어·생활 문장·카페이고 자모 문항은 없다.
2. 홈의 시작 버튼은 활성화되어 있다. 버튼을 누른다.
3. 입력할 수 있는 세 문항이 있음에도 `start('jamo')` 때문에 빈 목록으로 진입하여 “No questions are available.”만 보인다.
4. 단계 목록에서도 자모 0/0 버튼이 활성화되어 동일한 빈 화면으로 이동한다.

기대: 추천 시작은 사용 가능한 첫 단계로 연결하고 버튼 문구도 그 단계와 일치해야 한다. 문항이 없는 단계는 비활성 및 이용 불가 안내를 제공한다. 모든 문항이 없을 때의 기존 전체 비활성 처리는 유지한다. 최소 세 문항 검수 후 첫 흐름을 수용하는 계획에 직접 영향을 주므로 수정이 필요하다.

수정 재확인: 세 씨앗 fixture에서 “Start with words”를 선택하면 실제 입력란이 표시된다. 자모 단계는 비활성화되고 이용 불가 안내가 표시된다. 독립 fixture 통과.

### RU-02 · 확인 UI의 언어·기본 취소 포커스 계약이 구현되지 않음

위치: `src/App.tsx:63`의 `goHome()`, `src/App.tsx:86`의 `deleteData()`, `src/App.tsx:106`의 연습 언어 `onChange`; `src/components/PracticeSession.tsx:147`의 중단 버튼. 라인은 최초 재현 시점이다.

확인한 동작:

1. 단어 연습에서 입력한 뒤 연습 언어를 바꾸면 앱은 `window.confirm()`을 호출한다. 독립 fixture가 이 호출을 확인했다.
2. 코드에는 D002의 취소/계속 버튼, 기본 취소 포커스, Esc 취소, 닫은 뒤 호출 컨트롤 복원을 제어하는 확인 UI가 없다. `window.confirm`의 본문만 앱 UI 언어로 전달된다.
3. 학습 이탈과 두 삭제 동작도 같은 native confirm에 의존한다. 중단 버튼은 확인 없이 곧바로 정지 화면으로 이동한다.

기대: 앱의 세 언어 메시지와 명시적 취소/실행 버튼을 가진 확인 UI로 이탈·연습 언어 변경·삭제·중단을 처리한다. 기본 포커스는 취소/계속, Esc는 취소, 포커스는 창 안에 유지하고 닫을 때 호출 컨트롤로 돌린다. D002 §2.1, §3, §9의 계약이다. 특히 삭제 실행과 취소를 별도 레이블로 구분해야 한다.

이 재현은 native confirm을 실제 브라우저에서 조작한 결과가 아니다. 코드·jsdom에서 앱이 언어와 포커스를 제어할 수 있는 UI를 제공하지 않는 사실을 확인했다. 수정 후에도 실제 키보드/보조기술 검증은 별도로 남긴다.

수정 재확인: 앱 `ConfirmDialog`로 언어 변경·이탈·삭제·중단을 연결하고 `window.confirm`을 제거했다. KO/EN/VI 각각에서 취소/계속과 실행 버튼 번역, 취소 기본 포커스, Tab 순환, Shift+Tab, Esc 취소, 호출 언어 컨트롤 포커스 복원, 취소 시 원문·언어 유지, 확인 시 언어 변경과 빈 입력 재시작을 독립 jsdom fixture로 확인했다. 중단은 확인 콜백 안에서만 실행하며 조합 상태를 다시 확인한다. 삭제·이탈도 같은 확인 컴포넌트를 사용하는 것을 코드로 확인했다. 이 결과는 실제 브라우저의 native 키보드·스크린리더 조작을 대체하지 않는다.

## 읽기 검수에서 확인한 구현과 한계

- UI 언어와 연습 언어는 별도 상태·컨트롤이며 해석 세 언어는 각각 `lang` 속성으로 문항 아래 렌더된다. 기본 학습에는 숨김 버튼이 없다.
- 복습 준비 화면은 해석 표시가 기본이고 문항 원문을 렌더하지 않는다. 숨김 시작은 해석 DOM을 렌더하지 않는다. 같은 방문의 `contentId:revision` 노출 집합은 숨김·즉시 재시작·준비 화면 왕복에 보존된다.
- 첫 타자·의미 답과 재시도 결과는 구분되어 표시된다. 의미 과제가 없는 자모는 의미 결과 없음으로 표시한다. 이전 검수에서 지적한 창 이탈·CPM·언어 변경 문제는 별도 검수 보고서를 따른다.
- 세 언어 메시지 객체는 공통 `Messages` 타입을 따르며 입력 레이블, 버튼, 라디오 그룹, 텍스트 정오 안내가 있다. 번역의 자연스러움과 교육 적합성을 승인한 것은 아니다.
- CSS에 키보드 focus-visible 규칙과 좁은 폭 레이아웃이 있다. 실제 렌더링 대비·200/400% 확대·화면 읽기 검사는 하지 않았다.
- 현재 오디오 자료는 없고 앱은 미제공 상태를 표시한다. 모의 플레이어 검사와 실제 음원·발음·권리 검수는 다르다.

브라우저 제어는 조정자 세션에서 정책 연결 오류로 실패한 상태다. 이 검수는 다른 브라우저 자동화로 우회하지 않았다. 실제 Chrome/Edge 조작, Windows IME, Telex/VNI, 물리 키보드, 스크린리더, 원어민·교육 전문가 검수는 **미실행**이다.
