# MH-001 · 한글 IME 준비와 합성 검증 근거

기록일: 2026-09-30 · 실행자: Harness 입력·채점 개발 에이전트

**판정: 실제 OS IME 수용은 Blocked. 프로브 준비와 합성 검증만 실행했다.**

연결: [MH-001](../tickets/MH-001.md), [MH-007](../tickets/MH-007.md), [D003](../D003-input-scoring.md), [T001](../T001-validation-plan.md)

## 산출물과 임시 구현 범위

- [로컬 관찰 프로브](../../public/ime-probe.html): `npm run dev` 후 `/ime-probe.html`에서 사용한다. 정해진 fixture의 이벤트를 탭 메모리에만 기록하며 사용자가 복사를 선택할 수 있다. 네트워크 전송·자동 영구 저장은 없다.
- [입력 제어](../../src/input/usePracticeInput.ts): uncontrolled input, DOM 소유권과 epoch 검사, 동기 제출 잠금, 명시적 재시도, 마지막 확정값 중단·재개를 구현했다.
- [합성 회귀 검사](../../tests/input.test.tsx): 실제 IME 관찰에서 얻은 로그가 아니라 설계한 이벤트 순서·문자열 fixture다.

프로브와 앱은 입력란 Enter를 제출에 연결하지 않는다. 조합 중에는 DOM 값을 정규화하거나 덮어쓰지 않는다. 붙여넣기·드롭·관찰된 replacement는 해당 시도의 도움 표식을 유지한다. 새 질문·재시도·중단은 이전 노드의 늦은 이벤트를 차단한다. 창 비활성화·탭 숨김은 입력을 중단하고 마지막 확정값만 재개한다.

### 실제 로그 확보 전의 보수적인 임시 정책

`compositionend` 후에는 `settling` 상태를 유지한다. 뒤따르는 `input`만으로 안정화가 증명됐다고 가정하지 않는다. 첫 버튼 활성화는 전체 DOM 값을 확인하고 **제출하지 않으며**, 다음 별도 활성화에서 제출한다. 두 번 클릭의 `detail > 1`과 버튼의 키 반복은 차단한다. 고정 시간 지연·deprecated keyCode·단일 isComposing 플래그로 종료를 추정하지 않는다.

독립 검수에서 첫 확인 뒤 늦은 noncomposing `input`이 다른 값으로 바뀌는 경계를 발견해 앱 입력 제어를 수정했다. 확인한 `한` 뒤 `한국`이 도착하면 다시 `settling`으로 돌아가고, 새 확인 → 다음 별도 제출 순서를 요구한다. 늦은 값은 새 확인 전 중단·재개 값에도 포함하지 않는다. 값이 실제로 바뀌지 않은 늦은 이벤트에는 불필요한 확인을 추가하지 않는다.

따라서 조합을 사용하면 확인 버튼을 추가로 눌러야 하는 사용성 제약이 있다. 이 방식은 실제 Windows 검증을 대신하지 않으며, MH-001/002 로그를 얻은 뒤 지원 환경의 최종 이벤트 순서에 맞춰 변경·재검증해야 한다. MH-007의 정식 수용 조건을 충족한 것으로 처리하지 않는다.

## 현지 검수자의 다음 절차

1. Chrome/Edge 각각 실제 실행 버전, OS build, 두벌식 설정, 키보드 종류를 기록한다.
2. 프로브에서 한글 고정 fixture를 선택하고 새 관찰을 시작한다. `ㅎ → 하 → 한`, 확정, 취소, Backspace, 선택 교체를 수행한다.
3. 조합 중 Enter·Tab·버튼 클릭과 확정 후 새 버튼 활성화를 각각 별도 관찰로 수행한다. 같은 행동이 확정과 제출에 함께 사용되지 않는지 확인한다.
4. 조합 도중 문제 전환 후 이전 이벤트가 새 epoch의 값·카운터를 바꾸지 않는지 관찰한다. 로그에는 실제 이벤트와 별도 합성 재현을 구분한다.
5. 고정 fixture만 포함한 JSON 로그를 환경·절차와 함께 보관하고 예상·실제·결함을 기록한다. 실제 관찰로 D003의 안정화 정책을 결정한 뒤 앱 통합에서 다시 검사한다.

이 기록은 정식 IME 수용, 브라우저 지원 확정, 콘텐츠 검수 또는 학습 효과 근거가 아니다.
