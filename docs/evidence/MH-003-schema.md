# MH-003 · 콘텐츠 스키마와 로컬 저장 검증 근거

기록일: 2026-09-30 · 환경: Windows / Node v22.23.1 / npm 11.4.2 / Vitest 5.0.2.

## 구현

- [타입](../../src/content/types.ts), [검증기](../../src/content/validate.ts), [로더](../../src/content/index.ts)는 [D004](../D004-content-data-rights.md)의 개념·언어 변형·풀이·의미 보기·검수·출처 계약을 구현한다.
- `loadContent('preview')`는 구조가 유효하고 보류되지 않은 초안을 반환한다. 기본값과 `release`는 모든 검수 영역의 승인 근거 및 묶음 버전을 요구한다. 현재 release 결과는 **0개**다.
- 검증 결과는 개념 인덱스와 정확한 필드 경로를 반환한다. 일반 문항 손상은 해당 개념을 제외하며 중복 개념 ID/단계 순서와 모르는 구조 버전은 묶음을 차단한다.
- 장부 ID는 콘텐츠가 자체 주장한 목록이 아닌 로더의 실제 장부 목록과 대조한다. 미등록 참조·권리 거절/재확인 상태는 preview에서도 제외한다. 미승인 오디오·이미지 참조도 제공하지 않는다.
- 이 검사는 교육·번역·권리 전문가의 판단이나 연결된 승인 근거 문서의 진위 검증을 대신하지 않는다. 새 승인 레코드는 실제 검수 담당과 증거 확인이 필요하다.

## 실행한 검사

명령: `npm test -- tests/content.test.ts tests/storage.test.ts`

최초 결과: 2개 파일, 25개 테스트 통과. 독립 검수 수정 후 같은 명령의 최신 결과: **2개 파일, 32개 테스트 통과**. [콘텐츠 테스트](../../tests/content.test.ts) 14개, [저장 테스트](../../tests/storage.test.ts) 18개(매개변수화 포함).

| 기본 또는 release 로드 | 초안 전체 제외 |

전체 통합 빌드·화면 검증 결과는 [Harness 기록](../I004-harness-development.md)을 따른다. 이 파일의 실행 결과는 콘텐츠·저장 모듈의 집중 검사다.

### 독립 검수 이후 수정 루프

[독립 검수 보고](review-data.md)의 RD-01~06에 대응하여 다음을 수정했다. 구현 담당의 수정 검증과 독립 검수 담당의 최종 판정은 구분한다.

| 항목 | 수정·회귀 결과 |
|---|---|
| RD-01 | 승인 scope의 선두를 `개념ID@개정 검수영역` 토큰으로 정확히 검사. 선택적 설명은 세미콜론 뒤에 둔다. `MH-C005@1 vi`는 해당 개정·영역 fixture에서 통과하고 `@10`, `viet`, 다른 언어는 제외 |
| RD-02 | 저장소가 없는 메모리 전용 모드의 학습 삭제는 메모리 기록을 지우고 설정 유지. 오래된 스냅샷 재저장 차단. 실제 저장소 쓰기/삭제 실패는 계속 실패 반환 |
| RD-03 | `retry`는 별도 결과·집계에만 기록하고 기존 최초 오답 큐를 생성·변경·해결하지 않음. 새 복습 첫 답의 입력·무힌트 의미 해결 조건 유지 |
| RD-04 | 최근 이벤트의 개념·개정·언어·산식·환경·도움 그룹과 해당 ID의 집계가 일치해야 함. 복습 큐의 마지막 이벤트도 같은 개념·개정·언어에 속해야 함. 중복 큐와 마지막 결과 불일치 차단 |
| RD-05/06 | 한국어 오답 풀이를 조사 없이 명사를 분리하는 문장으로 수정. EN/VI 자모 변형은 해당 언어 입력 안내로 변경. 원고 전체 개정 2, 모든 검수 draft 유지 |

독립 담당이 작성한 원본 재현 fixture도 수정하지 않고 `node_modules\.bin\vitest.cmd run --config .local/review-data/vitest.config.ts`로 실행했다. 결과는 **4개 통과**다. 승인 사례는 가상 unit fixture이며 실제 콘텐츠를 승인한 기록이 아니다.

## MH-011 로컬 저장 선행 구현

[저장 어댑터](../../src/storage/index.ts)는 한 키 `maihangul.state`, schemaVersion 1, 원시 입력 없는 완료 결과를 사용한다.

- 손상·미래 버전·알 수 없는 구버전·읽기 오류는 원래 키를 보호한다. 메모리에서 학습을 계속해도 저장 성공으로 반환하지 않는다. 기존 배포 버전이 없어 v0 migration을 임의로 만들지 않았다.
- 쓰기 실패 후 탭 메모리 결과를 보존하며 명시적 저장 재시도에서 성공 여부를 반환한다. `storage` 이벤트 또는 쓰기 전 값 차이를 감지하면 자동 저장을 중단한다. 다중 탭 원자 병합은 제공하지 않는다.
- 집계는 개념/개정/언어/산식/환경/연습·복습/도움/중단/비교 자격을 구분한다. 첫 결과와 재시도는 별도 기록한다.
- `recentAttempts`는 개별 `completedAt` 기준 90일, 최대 200개다. 누적 집계·복습 큐와 마지막 결과는 유지한다. 오래된 동일 이벤트가 다시 완료 수를 늘리지 않도록 집계에 원문 없는 `attemptIds`를 보존한다. 이 ID 목록은 학습 기록 삭제 때 제거되며 저장량이 장기간 증가할 수 있다. 용량 실패는 메모리 모드로 처리한다.
- 의미 복습은 `practiceMode=review`, `attemptKind=first`, 해석 도움 없음, 첫 의미 답 정답일 때만 해결한다. 학습 성공·힌트 후 성공·같은 시도 재선택으로 기존 의미 오답을 지우지 않는다.
- 학습 기록 삭제는 설정 유지, 전체 삭제는 앱 키만 제거한다. 메모리 전용 모드에서는 탭 메모리 기록을 지운다. 실제 저장소 쓰기·삭제 실패는 성공으로 표시하지 않는다. 동기 저장과 개정 번호 검사로 삭제 전 스냅샷의 재저장을 거부한다.

검사는 실제 브라우저 저장 차단·다중 탭 상호작용을 대체하지 않는다. 실제 IME, 화면 접근성, 언어 검수, 사용자 학습 효과, 운영 배포는 이 검사에서 검증하지 않았다.
