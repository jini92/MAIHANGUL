# 베트남어 입력 시연 독립 검수

기준일: 2026-09-30 · 검수자: `keyboard_review` · 기준 commit: `ba058ca`

## 범위와 현재 판정

Telex/VNI 학습 시연의 규칙, 지원 범위, 실제 입력·채점과의 분리, 도움 사용 기록, 재생 상태 정리를 검수했다. 최종 모듈·화면·통합 diff와 회귀 검사를 읽었으며, 이 범위에 미해결 P1/P2 문제는 없다. 실제 브라우저 및 전체 테스트 실행 결과의 정본은 [I008](../I008-vietnamese-simulation.md)이다.

이 시연은 지원 문구에 대한 설명용 프레임이다. Windows 입력기 설치, 실제 IME 내부 상태, 실제 키보드 입력, 원어민·교육 전문가 검수의 성공 근거로 사용하지 않는다.

## 규칙과 지원 범위

- 근거: [UniKey 공식 설명서 3.1~3.3](https://www.unikey.org/support/ukmanual.html). 웹 도구는 해당 URL을 가져오지 못했으며, 통합 담당이 저장한 공식 HTML을 읽어 대조했다. 로컬 HTML은 공개 소스에 포함하지 않는다.
- 기본 문자 뒤에 형태 부호를 입력하고 성조키는 단어 끝에 입력하는 교육용 순서를 사용한다. Telex의 `aa/ee/oo`, `aw/ow/uw`, `dd`와 VNI의 `6/7/8/9`, 성조 다섯 종류가 대조 대상이다.
- 공식 예시 `tieengs Vieetj` / `tie6ng1 Vie6t5`와 `dduwowngf` / `d9u7o7ng2`를 기준으로 삼는다. 문서에는 단독 `w`, 부호 삭제·교체, 형태 부호 지연 입력 등 추가 동작이 있지만 이번 시연은 그 전체 엔진을 구현한다고 주장하지 않는다.
- 현재 콘텐츠의 20개 베트남어 목표와 명시된 예시에 제한한다. 지원하지 않는 입력은 임의의 Telex/VNI 순서로 안내하지 않아야 한다. Unicode NFC와 대문자·공백·구두점 보존을 확인한다.

## 순수 모듈 읽기 검수

[모듈](../../src/keyboard/vietnameseSimulation.ts)과 [전용 검사](../../tests/vietnamese-simulation.test.ts)를 대조했다. 현재 문항에 쓰이는 단어·공식 예시 단어·형태표의 일곱 글자를 명시한 단어 목록으로 제한한다. 해당 단어들의 대소문자 조합과 허용 구두점은 지원하고, 미지원 단어·기호가 하나라도 있으면 부분 안내 없이 빈 계획을 반환한다.

형태키는 기본 문자 직후, 성조키는 단어 끝에 넣는다. 대문자 기본 키의 Shift와 소문자 형태·성조키를 구분하고, 매 프레임을 NFC로 만든다. 공식 두 문구의 키열 및 `chào`, `đường`, `nước`의 명시적 중간 프레임 검사가 있다. 마지막 프레임 일치만으로 규칙 검증을 대신하지 않는다. DOM·학습자의 실제 입력·OS 설치 상태를 읽거나 변경하는 코드는 없다. 이 범위에서 P1/P2 문제를 발견하지 못했다.

모듈 담당은 전용 검사 **104개 통과**를 보고했다. 검수자는 테스트 소스를 읽었고 같은 테스트를 중복 실행하지 않았다.

## 화면·입력 통합 검수

[시연 컴포넌트](../../src/components/VietnameseSimulator.tsx), [연습 통합](../../src/components/PracticeSession.tsx), [자판](../../src/components/KeyboardGuide.tsx), 세 언어 안내 및 스타일을 검수했다.

- 실제 입력값을 시연 프레임으로 덮어쓰거나 이벤트를 합성하지 않는다. 시연 중 필드는 읽기 전용이며 제출 버튼을 비활성화하고 제출 핸들러에서도 다시 차단한다. 닫기는 실제 입력 필드로 포커스를 돌린다.
- 열기 시 pointerdown·키보드 활성화·click에서 현재 controller 상태를 조회한다. 조합 중 시작된 포인터 요청도 기억하므로 클릭 전에 조합 상태가 바뀌었다는 이유로 열리지 않는다. composing/settling 차단과 기존 확정 처리 계약을 유지한다.
- `demoUsed`는 채점에 전달되는 `assisted`에 합쳐진다. 닫기·재입력에서는 유지하고 다음 문제·명시적 문제 재시작에서 초기화한다. 도움 사용 사유로 속도 표시·비교에서 제외하며 정확도는 실제 제출값을 사용한다. 시연 시간과 키 개수를 점수로 만들지 않는다.
- 순수 입력 controller·채점 산식·저장 모듈·기존 콘텐츠 파일에 변경이 없는 것을 diff로 확인했다. 시연 Telex/VNI 선택은 실제 입력 방식 설정을 바꾸지 않는다.
- 자동 재생은 취소 가능한 타이머를 사용한다. 일시정지·방법 변경·대상 변경·unmount·창 이탈에 정리한다. UI 언어만 바꾸면 선택 방식과 프레임을 유지한다.
- 시연 키에는 별도 점선 표시와 범례를 쓰고 실제 누른 키 강조는 시연 중 중지한다. 기존 자판의 키보드 스크롤을 유지한다. 시연 목록 자동 스크롤은 목록 내부에 한정된다.
- 세 언어의 제목·설명·미지원 안내·도움 기록 안내와 native 버튼/선택상자를 확인했다. 시연 패널의 `id`와 열기 버튼의 `aria-controls` 연결도 최종 소스에서 확인했다.

## 검수 중 수정과 검증 근거

| 항목 | 발견·수정 및 최종 확인 |
|---|---|
| 경계 버튼 조작이 연습을 중단시킴 | 통합 담당이 실제 브라우저에서 초기화 버튼의 disabled 전환으로 포커스가 사라지는 문제를 발견했다. 최종 소스는 초기화·이전 첫 단계·다음 마지막 단계에서 상태 변경 전에 재생 버튼으로 포커스를 옮긴다. 회귀 검사는 세 경계에서 포커스와 연습 유지 상태를 확인한다. 실제 window blur/visibility 중단 처리는 유지한다. |
| 좁은 화면 본문 가로 넘침 | 통합 담당이 390px 브라우저에서 발견했다. 최종 diff의 `minmax(0, 1fr)`와 시연 영역의 `min-width:0`을 확인했다. 통합 담당은 본문 폭 정상화와 자판 내부 스크롤을 재확인했다고 보고했다. |
| 시연 패널 접근성 연결 | 검수자가 누락된 연결 후보를 전달했다. 최종 패널 `id="vietnamese-demo"`와 열기 버튼 참조가 일치한다. |

UI 담당은 [전용 UI 검사](../../tests/vietnamese-simulator-ui.test.tsx) **13개 통과**, TypeScript·diff 검사 통과를 보고했다. 검수자는 검사 소스를 읽어 입력 보존, 조합·settling 차단, 닫기 후 포커스, 방법·UI 언어 전환, 도움 기록 지속·다음 문제 초기화, 경계 버튼 및 타이머 검증 범위를 확인했다. 전체 테스트와 실제 브라우저 검사를 중복 실행하지 않았다.

위 합성 이벤트 검사는 앱의 처리 경계를 확인한다. 실제 Windows Telex/VNI 키 입력이나 OS 설치 검증 결과로 확대하지 않는다.

이 검수자의 변경 범위는 이 문서뿐이다. 제품 코드는 직접 수정하지 않는다.

## 후속 검수 · 베트남어 학습 홈과 진입

사용자의 베트남어 학습 화면 미노출 보고에 따른 후속 검수다. 직전 로컬 변경이 포함된 `.local/vi-entry-followup-baseline-20260930`의 사본을 비교 기준으로 사용한다. 위 시연 자체의 검수와 이번 학습 홈 노출 문제를 구분한다.

기존 홈은 연습 언어가 베트남어여도 한국어 과정 제목·설명·자모 시작 버튼·`R/ㄱ` 안내를 표시했다. 수정 범위는 현재 콘텐츠의 20개 베트남어 목표를 홈과 단계 진입에 명확히 보여주는 것이다. 새로운 독립 전체 교육과정이나 전문 검수 완료를 의미하지 않는다.

**후속 최종 소스 판정: 미해결 P1/P2 없음.** 위 사본과 최종 App·PracticeSession·i18n·스타일을 대조했으며 다음을 확인했다.

- `learningCopy(uiLocale, practiceLanguage)`가 베트남어 연습 여부에 따라 과정 제목·설명·단계명을 고른다. 세 UI 언어는 이 내용을 각각 번역하며 연습 언어를 바꾸지 않는다. 홈 제목·문서 제목·시작 버튼·단계 카드·연습 단계 표시에 같은 구분을 적용한다.
- 단계별 예시는 실제 `variants.vi.targetText`에서 가져온다. 문항 수와 완료 수는 콘텐츠·현재 언어·현재 revision에 맞는 기존 계산을 유지한다. 새 문항 ID나 가짜 진도를 추가하지 않는다. 한국어로 돌아가면 기존 한국어 제목·설명·진입을 유지한다.
- 주 시작 버튼은 베트남어 직접 연습으로 진입한다. 보조 Telex/VNI 버튼은 이용 가능한 첫 생활 문항(없으면 첫 문항)의 시연을 연다. `initialDemoOpen`과 `demoUsed`의 VI 가드가 일치해 처음부터 읽기 전용·제출 잠금·도움 사용을 적용한다. 닫기 후 직접 답을 제출하면 `assisted:true`가 저장된다. 다음 문제·일반 시작·복습·언어 변경에서는 이 자동 시연 상태를 해제한다.
- release 모드에 검수된 콘텐츠가 없으면 시작을 비활성화하고 시연 바로가기를 제공하지 않는다. preview의 초안 배너와 콘텐츠 승인 필터를 유지한다.
- MH-C001~004만 revision 2에서 3으로 바뀌었다. 이 네 문항의 VI 해설은 각 목표의 뜻을 설명하도록 바뀌었으며, KO·EN variant와 VI 목표 문자열은 독립 JSON 비교에서 모두 동일했다. 나머지 16개 문항은 동일했다. 모든 검수 영역의 `draft`, 담당자·날짜·근거의 null 상태와 미발행 packVersion을 유지한다. 전문 번역·교육 수용으로 간주하지 않는다.
- revision은 기존 concept 단위 계약을 따른다. 네 문항의 이전 기록은 삭제하지 않지만 현재 revision과 다른 과거 완료는 최신 진도 합계에서 제외된다. 이 영향은 데이터 변조나 기록 삭제와 구분한다.

FE 담당은 [진입 회귀 검사](../../tests/vietnamese-learning-entry.test.tsx) 6개를 포함한 관련 45개 검사와 TypeScript·diff 검사 통과를 보고했다. 검수자는 세 UI 언어에서 실제 VI 문항 진입, 직접 시연의 도움 기록·다음 문제 초기화, 언어 전환, KO 복귀, release 미검수 콘텐츠 차단의 테스트 소스를 읽었다. 콘텐츠 담당은 [콘텐츠 검사](../../tests/content.test.ts) 19개 통과를 보고했다. 이 검사는 첫 네 문항의 뜻풀이·KO/EN 보존·revision scope·미승인 상태를 확인한다. 전체 테스트·실제 5173/Pages 브라우저 검증은 통합 담당이 수행하며 이 읽기 검수만으로 런타임 성공을 선언하지 않는다.

공개 범위 보완 검사에서는 이번 변경 후보 27개 파일의 자격증명·비공개 키·긴 인증 리터럴·서명 URL 패턴 탐지가 0이었다. `.local/` 사본·`.mcp.json`·`.codex/config.toml`·`.claude/settings.local.json`이 실제 ignore 규칙에 포함되고 변경 후보에 없는 것을 확인했다. 이 결과는 검사 패턴의 범위이며 비밀 부재의 포괄적 보증은 아니다. 사용자 push·배포 승인은 통합 담당이 확인했으며 실제 원격 반영·배포 성공은 [I007](../I007-github-pages.md)의 실행 결과를 따른다.

이 후속 검수에서도 제품 코드를 수정하거나 전체 테스트를 중복 실행하지 않았다. 변경 범위는 이 문서의 후속 검수 절이다.
