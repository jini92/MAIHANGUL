# I006 · Stitch 시안과 Blender 자산의 실제 FE 적용

기준일: 2026-09-30 · Harness preset: default · 상태: 로컬 구현·자동/브라우저 검사·독립 검수 완료

## 목표와 계획

사용자는 두 도구의 연결에 이어 디자인 제작 결과를 실제 앱에 적용하도록 요청했다. 이번 루프에서는 Stitch 화면을 React UI로 옮기고, Blender MCP로 직접 만든 3D 자판 렌더를 홈에 표시한다.

- 시작점: master `01288d88d412a81a41bb76650901df58cbfc6253`와 이전 미커밋 구현. 변경할 기존 파일 8개를 `.local/stitch-blender-before/`에 보존했다.
- 가정: PC 두벌식 학습을 중심으로 하고 KO/EN/VI UI·입력 지원과 기본 해석 표시를 유지한다. 홈의 3D 자판은 입문 안내용 이미지이며 연습 화면의 동작하는 DOM 자판을 대체하지 않는다.
- 대안: 브라우저에서 3D 모델을 실시간 렌더하면 WebGL 의존성·로딩 비용·접근성 검증이 늘어난다. 이번 목적에는 Blender에서 렌더한 정적 이미지와 실제 DOM 자판이 충분하다.
- 변경 범위: 홈 이미지·화면 구조·자판 색상/깊이·학습 진행 표시·필요한 3언어 UI 문구. 입력 확정·채점·진도 저장 계약은 보존한다.
- 추가 요청: 자판을 보기 좋게 어느 정도 투명하게 표현. DOM 배경·키캡에 반투명 표면을 적용하고 Blender 재질도 부분 투과로 조정한다. 글자·강조 키의 가독성을 유지한다.
- 복잡도: 중간. 외부 시안 생성, Blender 모델/렌더, 기존 React 흐름의 시각 변경을 통합한다.

## 성공 기준

1. Stitch의 실제 화면 결과와 적용한 UI 요소를 파일·컴포넌트로 연결한다. 단순히 시안을 만들었다는 이유로 적용 완료라 하지 않는다.
2. Blender의 실제 MCP 명령으로 생성한 모델·재현 스크립트·렌더를 보존하고, 앱의 `<img>`가 해당 렌더 파일을 읽는 것을 브라우저에서 확인한다.
3. PC 화면에 목표·해석·입력·5줄 자판이 읽기 쉬운 크기로 표시된다. 좁은 화면의 스크롤·키보드 포커스·언어 설정을 확인한다.
4. 기존 회귀 검사와 빌드가 통과하고 별도 에이전트가 소스·출처·입력 보호를 검수한다.
5. 자체 제작 자산·사용한 도구·검수 한계는 권리 장부에 기록한다. 실제 OS IME·원어민 검수·학습 효과를 성공 처리하지 않는다.

## 역할

- Stitch·통합: 기존 비공개 시안 수정, 실제 결과 관찰, 적용 기준·브라우저 검사.
- Blender 제작: 새 제작 씬에서 직접 모델링·렌더, 편집 원본·재현 스크립트·실행 근거.
- FE 구현: Stitch 결과를 React/CSS에 적용하고 Blender 이미지를 홈에 연결.
- 독립 검수: 제작에 참여하지 않은 에이전트가 변경 범위·접근성·다국어·권리 근거를 검토.

외부 공개, commit/push, 배포, 유료 생성, 기존 사용자 씬 삭제는 수행하지 않는다. Stitch에는 필요한 공개 수준의 디자인 개요만 보낸다.

## 결과

### 실제 도구 사용과 반영

- **Stitch**: 기존 비공개 프로젝트 `12010067946882988516`에서 실제 `edit_screens`로 화면 `79840c32af214556a77c16cf6aaa5615`를 생성했다. [요청·원본 HTML/PNG·메타데이터](../.stitch/README.md)를 보존했다. 얇은 헤더, 실제 4단계 진도, 목표 타일·키 위치 안내, 세 언어 해석 구획, 입력 작업행, 자판 표시를 React/CSS로 구현했다. [컴포넌트 반영표](evidence/stitch-fe-mapping.md)가 구체적인 정본이다.
- **Blender**: 실제 MCP 명령으로 새 씬에서 5행·61키와 자체 재질·조명·카메라를 만들고 렌더했다. [편집 모델](../design/blender/keyboard-studio.blend), [재현 스크립트](../design/blender/create-keyboard.py), [실행 근거](evidence/blender-asset.md)를 보존했다. 최초 빈 검증 씬은 그대로 남겼다.
- **제품 연결**: 홈의 `<img>`가 [1400×900 WEBP](../public/assets/keyboard-studio.webp)를 읽는다. 이미지 용량은 144,316 bytes다. 브라우저에서 로딩 완료와 실제 자연 크기 1400×900을 확인했다. 빌드 복사본과 소스 이미지 SHA256은 `c7659ea547eafac3b2a4cd007c82cab0d8e06f4ca0ed9b563abd2946160ca0dd`로 일치했다.
- **반투명 처리**: DOM 자판 배경은 52%, 일반 키캡은 68% 불투명도다. 배경 흐림과 얇은 경계를 사용하되 글자는 불투명하게 유지한다. Blender 키캡은 transmission 0.24/alpha 0.94, 본체는 0.38/0.86이며 글자·파란 R·주황 Enter는 불투명 재질이다. CSS alpha와 Blender transmission은 서로 다른 속성으로 같은 수치의 투명도를 뜻하지 않는다.
- **출처**: Noto Sans CJK KR Medium 2.004의 공식 커밋·OFL 원문·NOTICE를 기록했다. 글자는 모델 메시로 변환했고 최종 모델은 Windows 폰트나 Noto 폰트 파일을 내장하지 않는다. 자체 UI·3D·폰트의 근거는 [권리 장부 MH-R003~005](../content/ASSET-LICENSES.md)를 따른다.

### Harness 루프 요약

Plan에서 실제 도구 산출물이 앱에 표시되는 것을 완료 기준으로 정했다. Build에서 Stitch 시안을 옮기고 Blender 자산을 제작했다. Eval에서 생성 HTML의 잘못된 Enter/R 안내·가짜 단계·전역 키 이벤트·외부 CDN을 제외하고, 실제 진도 계산·OFL 글꼴·반투명 표면을 확인했다. 사용자 추가 요청은 같은 루프에 반영했다. 별도 검수 에이전트의 최종 판정과 문서·diff 검사를 마쳐 로컬 디자인 업데이트 범위를 완료했다.

이번 검증에 사용한 원칙은 실제 앱 진입점에서 결과를 확인하고, 입력 안내와 IME·채점 계약을 분리하고, 실행한 검사와 미검증 외부 환경을 구분하는 것이다. 새 기능을 위해 런타임 3D 의존성이나 외부 폰트 요청을 추가할 필요는 없었다.
