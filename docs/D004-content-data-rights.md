# D004 · 콘텐츠·데이터·권리 설계

상태: **Draft / 미구현 / 콘텐츠 미검수** · 기준일: 2026-09-30

요구사항 정본: [A001](A001-PRD.md) · 모듈 경계: [D001](D001-architecture-overview.md) · 화면: [D002](D002-learning-game-ux.md) · 입력 정책: [D003](D003-input-scoring.md) · 검증: [T001](T001-validation-plan.md)

대상 요구사항: R01, R02, R03, R04, R06, R08, R10, R14, R16, R18, R19. 개발 순서는 [I002](I002-development-plan.md), 티켓 상태는 [티켓 목록](tickets/INDEX.md)이 정본이다.

## 1. 설계 결정과 콘텐츠 범위

- 최초 묶음은 **20개 학습 개념**이다. 각 개념에 한국어·영어·베트남어의 짧은 입력 변형을 두어 세 언어 입력을 첫 MVP에서 지원한다. 60개의 독립 교육과정을 만드는 범위는 아니다.
- 기본 연습 언어는 한국어다. 영어·베트남어 변형은 같은 개념의 의미나 자판 안내를 짧게 입력하는 연습으로 한정한다. 영어·베트남어 전체 교육과정은 후속 범위다.
- 모든 언어 변형은 원문 아래에 쉬운 한국어 풀이와 영어·베트남어 해석을 가진다. 화면 언어, 연습 언어, 복습 해석 표시 설정의 동작은 D002가 정본이다.
- 콘텐츠는 정적 묶음으로 앱에 포함하는 방향이다. 작성용 CMS, 원격 콘텐츠 수집, 외부 번역 API는 첫 범위에 넣지 않는다. 이 문서는 데이터 계약이며 제품 데이터 파일은 아직 만들지 않았다.
- 자모·자판 문항은 한글 형태와 키 위치를 익힌다. 영어·베트남어 변형은 그 개념의 짧은 안내 단어를 연습하며, 영문 철자와 한글 발음의 일대일 대응을 주장하지 않는다. 실제 목표 문자열은 교육·번역 검수에서 결정한다.
- 이미지·음악·음성 없이 텍스트 보기로도 모든 필수 흐름을 완료한다. 그림과 음성을 도입하면 해당 자산을 별도 검수한다.

대상 사용자는 PC를 사용하는 베트남어 모어 성인 한국어 초급자라는 가정이다. 예문 난도·높임말·보기 수는 이 가정에 맞춘 초안이며 사용자 탐색에서 확인한다.

## 2. 콘텐츠 데이터 계약

아래 필드는 **설계용 정의**다. 타입 선언, 검증기, 실제 JSON 파일이 구현되었다는 뜻은 아니다. 작성 단계에서는 빈 번역을 `null`로 표현할 수 있으나, 학습자에게 제공하는 묶음에는 필수 필드가 모두 있어야 한다.

### 2.1 묶음과 개념

| 필드 | 형식·예 | 규칙과 책임 |
|---|---|---|
| `schemaVersion` | 양의 정수, 최초 제안 `1` | 구조 해석용. 앱이 모르는 버전은 로드하지 않음 |
| `packId` | `MH-CORE-01` | 최초 20개 묶음의 고정 ID |
| `packVersion` | `1.0.0` 형식의 버전 또는 `null` | 작성·개발 preview는 null 허용. 검수 수용 묶음은 버전 필수. 현재 발행된 버전 없음 |
| `concepts` | 개념 목록 | 학습자 제공 묶음은 아래 계약과 검수 게이트를 모두 통과해야 함 |
| `id` | `MH-C001` ~ `MH-C020` | 개념의 고정 ID. 삭제·폐기해도 다른 개념에 재사용하지 않음 |
| `revision` | 양의 정수 | 해당 개념의 원문·해석·보기·정답·미디어 참조 중 하나라도 바뀌면 증가 |
| `stage` | `jamo`, `word`, `daily`, `cafe` | 학습 단계. 기본 순서는 D002/R19에 따름 |
| `order` | 단계 안의 양의 정수 | 진행 순서. ID 문자열 정렬로 교육 순서를 추정하지 않음 |
| `learningGoal` | 짧은 작성자용 텍스트 | 배울 글자·단어·문법·의미를 명시 |
| `difficultyNote` | 작성자용 텍스트 | 새 어휘, 높임말, 입력 난도, 검수할 가정 |
| `variants` | `ko`, `en`, `vi` 각 하나 | 세 언어 변형은 모두 필수. 상세는 2.2 |
| `provenance` | 출처·작성 이력 | 상세는 2.4. 자체 작성·AI 보조 여부도 기록 |
| `review` | 개념·변형별 검수 묶음 | 상세는 3절. 승인 근거가 없는 상태는 `draft` |
| `lifecycle` | `active`, `quarantined`, `retired` | 작성 중에는 `active`여도 검수 전 학습자 제공 금지. 상태와 검수 게이트를 함께 검사 |

### 2.2 언어별 문제·해석·선택지

| 필드 | 형식 | 규칙 |
|---|---|---|
| `practiceLanguage` | `ko`, `en`, `vi` | `variants`의 키와 같아야 함. UI 언어와 독립 |
| `targetText` | 일반 문자열 | 입력할 하나의 정답 원문. MVP는 대체 정답 목록을 두지 않음 |
| `explanations.ko` | 일반 문자열 | 쉬운 한국어 풀이. 원문을 그대로 반복하는 것만으로 대체하지 않음 |
| `explanations.en` | 일반 문자열 | 해당 변형의 영어 해석. 어조·사용 상황 포함 |
| `explanations.vi` | 일반 문자열 | 해당 변형의 베트남어 해석. 성조·호칭·자연스러움 검수 |
| `usageNote` | `ko`, `en`, `vi` 문자열 | 꼭 필요한 상황·높임말 설명. 불필요하면 세 값 모두 빈 문자열로 일관되게 둠 |
| `keyboardHint` | 세 언어 일반 문자열 또는 `null` | 자모·자판 단계의 안내. OS 입력기 설정 완료 여부를 앱이 추정하지 않음 |
| `meaningTask` | 의미 과제 또는 `null` | 자모·자판은 `null`로 두고 의미 점수는 `해당 없음`. 단어·생활 문장·카페에는 필수 |
| `audioRef` | 자산 ID 또는 `null` | MVP 제안은 검수된 한국어 음성만 선택 지원. 기본값 `null` |

각 `meaningTask`는 다음 구조를 갖는다.

| 필드 | 규칙 |
|---|---|
| `kind` | `selectMeaning` 또는 `selectOrder`. 카페는 `selectOrder` |
| `instruction` | 세 언어 안내 문구. 선택 행동을 설명하고 정답을 직접 드러내지 않음 |
| `options` | 3개의 보기. 각 보기의 고유 `id`, 세 언어 `label`, 선택적 `imageRef`를 기록. 같은 과제 안 보기 ID 중복 금지 |
| `correctOptionId` | 목록에 실제 존재하는 보기 ID 정확히 1개 |
| `feedback` | 정답 선택 이유를 `{ko,en,vi}`로 설명 |
| `feedbackByOptionId` | meaningTask의 독립 필드. 모든 보기 ID 각각을 `{ko,en,vi}` 설명에 매핑하며 오답도 구체적으로 설명 |
| `orderAttributes` | 카페는 정답의 음료·수량·온도 등 문장이 말한 속성만 기록. 비카페는 null. 문장이 말하지 않은 조건을 정답 기준에 추가하지 않음 |

보기는 UI 언어로 표시하고 의미 과제의 지시·풀이도 UI 언어로 읽을 수 있게 한다. 원문 아래의 세 언어 해석은 계속 유지한다. 각 변형의 보기와 정답 관계는 따로 검수한다. 한 변형의 정답 ID를 다른 언어 변형에 무조건 재사용하지 않는다.

이미지에만 답을 담지 않는다. 그림이 없어도 보기의 텍스트로 같은 선택을 할 수 있어야 한다. 자모 단계에서 의미 과제가 없는 것은 정답률 0%와 구별한다.

### 2.3 정답 원문과 입력 정책의 연결

- 입력 비교 정책은 [D003](D003-input-scoring.md) 하나를 정본으로 사용한다. 콘텐츠별로 별도의 느슨한 비교 규칙을 만들지 않는다.
- NFC 정규화 후 양 끝의 일반 공백 `U+0020`만 제거한다. 내부 공백·구두점·영어 대소문자·베트남어 성조는 보존하여 전체 문자열을 정확히 비교한다. 글자 수는 NFC 처리 뒤의 grapheme cluster를 기준으로 한다.
- `targetText`는 작성 단계에서 NFC 형식으로 저장하고 양 끝 `U+0020`, 탭·개행·보이지 않는 제어문자를 넣지 않는다. 단일 행의 짧은 목표만 쓴다. 검증기는 위반 위치를 작성자에게 알려준다.
- 자모 `ㄱ`을 완성 음절과 혼동하거나 베트남어의 다른 성조를 대체 정답으로 추가하지 않는다. 채점하기 어려운 콘텐츠는 정책을 조용히 완화하지 않고 문항을 수정·재검수한다.
- D003의 붙여넣기·속도 집계·언어별 비교 정책은 콘텐츠 모듈이 덮어쓰지 않는다.

### 2.4 출처·음성·자산 데이터

| 필드 | 내용 |
|---|---|
| `provenance.origin` | `original`, `adapted`, `licensed`. 현재 계획은 `original` |
| `provenance.createdBy` | 실제 작성자 또는 작성 방식. AI 보조가 있으면 도구와 사용 범위를 기록하며 사람 검수자로 표시하지 않음 |
| `provenance.createdAt` | 실제 작성일 |
| `provenance.sourceReferences` | 참고한 자료의 제목·URL·접근일·참고 범위. 없으면 빈 목록 |
| `provenance.assetRecordIds` | [ASSET-LICENSES](../content/ASSET-LICENSES.md)의 문장·번역 권리 기록 ID |
| `asset.id` / `asset.revision` | `MH-Axxx` 형식의 별도 고정 ID와 개정 번호. 예시는 예약 규칙이며 실제 자산 등록 아님 |
| `asset.kind` / `asset.file` | `text`, `translation`, `image`, `audio`, `font`, `dependency`와 프로젝트 안 상대 경로 |
| `asset.rightsRecordId` | 장부의 실제 항목 ID. 참조만 있고 항목이 없으면 사용 불가 |
| `audio.language` / `audio.transcript` | 언어와 실제 발화 원문. 대상 문항·개정 번호와 일치해야 함 |
| `audio.productionMethod` | 직접 녹음, 의뢰 녹음, TTS 등 실제 방식 |
| `audio.durationMs` | 파일 측정 후 기록. 현재 미측정 |
| `audio.review` | 발음·속도·높임말·잡음 검수와 이용·배포 범위 확인을 별도 기록 |

원문·해석·보기·출처 텍스트는 모두 일반 텍스트로 표시한다. 저장된 HTML을 실행하거나 원시 HTML로 렌더링하지 않는다. 파일 참조는 앱에 포함된 자산 목록의 ID만 해석하고, 작성자가 입력한 임의 원격 URL을 바로 재생하지 않는다. 출처 URL은 기록용 정보이며 자동 수집 지시가 아니다.

## 3. 검수 상태와 제공 게이트

### 3.1 검수 레코드

각 항목은 `status`, `reviewer`, `reviewedAt`, `scope`, `evidence`, `notes`를 갖는다. `status`는 `draft`, `inReview`, `approved`, `rejected`, `needsRecheck` 중 하나다. 승인 상태에는 실제 담당자, 날짜, 대상 개념·개정·언어, 근거 문서 경로가 필수다. 작성과 자동 필드 검사는 사람 검수를 대신하지 않는다.

| 검수 영역 | 확인하는 내용 | 담당 조건 |
|---|---|---|
| 한국어 교육 | 초급 난도, 자모 안내, 학습 목표, 뜻, 높임말·사용 상황, 정답 유일성 | 한국어 교육 내용을 검토할 수 있는 담당자 선정 필요 |
| 베트남어 | 모든 VI 원문·해석·보기·피드백의 성조, 자연스러움, 한국어 의미 대응 | 베트남어 검수 담당자 선정 필요 |
| 영어 | 모든 EN 원문·해석·보기·피드백의 자연스러움과 의미 대응 | 영어 검수 담당자 선정 필요 |
| 권리 기록 | 작성 이력, 출처, 권리자, 각 자산의 이용·변경·배포 근거 | 프로젝트 권리 검토 담당 선정 필요. 법률 판단이 필요한 쟁점은 별도 승인 |
| 음성 | 발음·내용·속도와 파일 품질 | 해당 언어 검수 및 제작·권리 근거. 오디오가 없으면 `해당 없음` |

현재 담당자와 검수 비용은 미정이다. 본 문서의 문장이나 상태 표시는 검수 완료 근거가 아니다.

### 3.2 단계별 수용 기준

1. **작성·개발 미리보기:** 20개 계획을 기반으로 세 언어 변형을 작성한다. `draft` 자료는 개발자 미리보기에서 `검수 전 초안`으로 표시하고 학습자 제공 묶음에서 제외한다. 개발 미리보기의 기능 확인은 콘텐츠 수용 완료로 기록하지 않는다.
2. **첫 한 문제 흐름의 수용:** 최소 3개 개념, **MH-C005(단어), MH-C011(생활 문장), MH-C017(카페)**의 세 언어 변형과 모든 해석·보기·피드백이 교육·VI·EN 검수 및 권리 기록 확인을 통과해야 한다. 나머지 자료는 초안으로 둘 수 있다. 세 개를 고른 이유는 짧은 단어, 문장, 입력 후 주문 선택을 모두 검사하기 위해서다.
3. **첫 MVP 콘텐츠 수용:** MH-C001~MH-C020 전부가 세 언어 변형을 포함하여 위 검수를 통과해야 한다. 최초 20개가 완료되어야 R16을 충족한다. 3개만 검수한 상태를 MVP 완료로 표시하지 않는다.
4. **음성 사용:** `audioRef=null`이면 음성 없이 수용 가능하다. 참조가 있으면 음성의 언어 검수와 장부의 사용·배포 근거까지 확인되어야 재생을 제공한다. 기본 오디오 비활성은 텍스트 학습의 완성을 막지 않는다.

개념 내용이 변경되면 영향을 받는 영역을 `needsRecheck`로 바꾸고 제공 대상에서 제외한다. 원문 변경은 교육·세 언어 의미 대응·선택지 및 관련 음성 검수를 다시 요구한다. 권리 근거 변경은 권리 상태도 다시 확인한다. 단순 오탈자라도 개정 번호와 변경 이력을 남긴다.

## 4. 최초 20개 자체 제작 문항 구성 계획

아래 한국어 원문은 이 설계를 위해 새로 작성한 **검수 전 초안**이다. 정확한 교육 내용·번역·권리를 승인한 자료가 아니다. EN/VI 목표 원문, 각 변형의 세 언어 해석, 보기와 피드백은 후속 작성·검수가 필요하다. 20개 모두 `draft`이며 제품 콘텐츠 파일·오디오·이미지는 아직 없다.

| 개념 ID | 단계 | 한국어 목표 초안 | 학습 목표·의미 선택 방향 | 현재 상태 |
|---|---|---|---|---|

## 5. 검증·누락·잘못된 콘텐츠 처리

### 5.1 작성 및 로드 단계 검사

구현할 검증기는 다음 오류를 개념 ID·개정·필드 경로와 함께 반환한다. 파일 전체를 콘솔에 출력하거나 학습자의 입력을 오류 보고에 넣지 않는다.

| 입력 조건 | 예상 결과 |
|---|---|
| 같은 ID가 두 번 등장하거나 같은 ID·개정에 다른 내용이 있음 | 해당 묶음 수용 실패. 작성 단계에서 중복을 고친 뒤 다시 검사 |
| `ko`, `en`, `vi` 변형 중 하나 또는 필수 해석이 비어 있음 | 해당 개념을 학습자 제공 목록에서 제외. 다른 언어 텍스트로 조용히 대체하지 않음 |
| 정답 ID가 보기 목록에 없거나 정답이 둘 이상 | 해당 개념 격리. 의미 과제를 시작하지 않음 |
| 단어·생활 문장·카페인데 의미 과제가 없음 | 해당 개념 격리. 의미 점수 0%로 우회하지 않음 |
| 리뷰가 미완료·재검수 필요이거나 승인 근거가 없음 | 개발 미리보기에서만 사용 가능. 학습자에게 검수 완료로 표시하지 않음 |
| 장부 참조가 없거나 사용 범위를 확인할 수 없음 | 관련 텍스트 개념 또는 자산 사용 보류. 사용할 자료를 다른 것으로 교체하면 재검수 |
| 선택 이미지가 없거나 사용할 수 없음 | 텍스트 보기로 진행. 이미지 부재 때문에 정답 정보가 사라지면 개념 격리 |
| 선택 음성 누락·재생 실패 | 오디오 모듈의 실패 안내 후 텍스트 학습 유지. 자동 외부 TTS 호출 없음 |
| 알 수 없는 `schemaVersion` | 묶음을 열지 않고 콘텐츠를 사용할 수 없다고 세 언어 UI로 안내 |
| 모든 개념이 제외됨 | 시작 버튼 대신 이용할 수 있는 학습자료가 없다는 안내. 빈 화면·무한 대기 방지 |

릴리스 전 묶음 검사는 한 개념이라도 필수 조건에 실패하면 전체 MVP 콘텐츠 게이트를 실패로 기록한다. 런타임 방어로 문제 개념을 제외하고 남은 검수 개념을 제공하는 동작은 이 완료 조건을 완화하지 않는다.

### 5.2 진행 중 오류·수정·진도 이력

- 시작할 때 검수·버전 조건을 통과한 묶음을 세션 동안 고정한다. 같은 시도의 중간에 콘텐츠 개정이나 정답을 바꾸지 않는다.
- 문제 표시 후 데이터 오류가 발견되면 현재 문제를 중단하고 `콘텐츠 오류로 결과를 기록하지 않았습니다`라는 UI 문구를 각 언어로 제공한다. 학습자의 오답으로 저장하지 않는다. 사용 가능한 다음 문제 또는 시작 화면으로 이동한다.
- 작성자는 문제 개념을 `quarantined`로 두고 원인·수정·개정·재검수 근거를 남긴다. 번역 누락을 발견한 즉시 임의 자동 번역으로 채워서 완료 처리하지 않는다.
- 학습 기록은 아래 대응표에 따라 콘텐츠를 참조한다. `conceptId`는 콘텐츠 객체의 `id`를 가리키는 참조명이며 별개의 ID를 생성하지 않는다. 저장 형태와 초기화·삭제·실패 처리는 D001이 정본이다. 콘텐츠 본문 전체를 진도 저장에 복제하지 않는다.
- 개정된 개념은 새로 복습할 수 있으나 과거 점수는 과거 개정에 남긴다. 과거 성취를 새 개정의 검증 결과로 자동 변환하지 않는다. 폐기된 개념은 신규 문제 목록에서 숨기고 과거 기록은 `이전 콘텐츠`로 읽을 수 있게 한다.
- 앱이 알 수 없는 콘텐츠 버전의 중단 상태는 자동 재개하지 않는다. D001/D002의 복구 안내에 따라 해당 개념을 새로 시작한다.

| D004 콘텐츠 필드 | D001 진도 저장 필드 | 대응 규칙 |
|---|---|---|
| `id` (참조명 `conceptId`) | `contentId` | 같은 `MH-Cxxx` 값 |
| 개념의 `revision` | `contentVersion` | 같은 양의 정수. 개념 내용의 개정 번호 |
| `practiceLanguage` | `variantLanguage` | 같은 `ko`, `en`, `vi` 값 |
| `packVersion` | `contentPackVersion` | 같은 콘텐츠 묶음 버전 |

D001의 저장 envelope에 있는 `revision`은 여러 탭의 저장 충돌을 감지하는 **저장본 개정 번호**다. D004의 개념 `revision`이나 자산 `asset.revision`과 다른 값이며 서로 복사하거나 비교하지 않는다. 콘텐츠 묶음의 `schemaVersion`도 저장 envelope의 `schemaVersion`과 각기 해당 구조만 설명한다.

## 6. 작성·교육·번역 검수 절차

1. **작성:** 작성 담당이 20개 개념의 목표·원문·보기·정답·풀이를 작성한다. 출처 참고가 있으면 문구와 함께 기록한다. 자동 생성 여부를 숨기지 않는다.
2. **교육 검수:** 한국어 교육 담당이 개념별 학습 목표·난도·자모 안내·높임말·정답 유일성을 확인한다. 학생의 문화·연령을 추정해서 부적절한 표현을 넣지 않았는지 확인한다.
3. **번역:** EN/VI 변형과 각 변형의 3개 언어 풀이·보기·피드백을 작성한다. 직역의 자연스러움만 보지 않고 원문의 의미와 실제 선택 정답이 같은지 확인한다.
4. **독립 언어 검수:** VI 담당과 EN 담당은 실제 대상 개정의 원문·보기·피드백을 각각 확인하고 수정 또는 승인 근거를 남긴다. 작성자 본인의 일괄 `approved` 처리로 대체하지 않는다. 담당자의 역할·독립성은 기록한다.
5. **교차 확인:** 한국어 교육 담당이 번역 후 높임말·의미 조건·정답 유일성이 유지되는지 확인한다. 수정된 필드가 다른 언어 해석에 영향을 주면 해당 언어 검수로 되돌린다.
6. **권리·묶음 확인:** 문장·번역·첨부 자산의 장부 ID와 사용 조건을 확인하고 필드 검사를 실행한다. 검수된 개정만 제공 묶음에 포함한다.
7. **학습자 화면 확인:** 향후 구현된 화면에서 세 언어 줄바꿈·기호·성조·보기 길이·해석 노출을 확인한다. 문서 검수가 화면 검증을 대신하지 않는다.

담당자 선정·유료 검수 의뢰·참여자 연락은 현재 문서 작성의 실행 범위에 포함하지 않는다. 필요한 역할과 전달 자료를 준비하고 외부 검수 의존성을 티켓에 남긴다. 학습 효과 판단은 [T001](T001-validation-plan.md)의 별도 사용자 탐색 계획을 따른다.

## 7. 오디오 사용·배포 및 권리 기록 절차

오디오는 기본 비활성이다. 사용 가능한 검수 자산이 없을 때 듣기 동작이 존재하는 것처럼 표시하지 않는다. 한국어 음성을 추가하려면 다음 자료가 필요하다.

1. 제작 방식·원문·녹음자 또는 서비스·생성일·파일·대상 문항 개정을 기록한다.
2. 자체 녹음도 목소리 제공자의 동의 범위, 서비스 이용 음성도 해당 조건과 결과물의 이용·변경·배포 범위를 확인하고 근거를 장부에 연결한다.
3. 비용·계약·법률 해석이 필요한 사항은 사용자 승인 대상으로 올린다. 공개 링크가 있거나 AI로 생성했다는 이유로 사용 가능 판정을 내리지 않는다.
4. 발음·속도·끊어읽기·높임말·대본 일치·파일 품질을 검수하고, 실제 플레이어에서 재생·실패·중단·다시 듣기를 확인한다.
5. 사용 근거 또는 검수 상태가 바뀌면 재생 대상에서 제외하고 텍스트 학습을 유지한다. 자동으로 다른 외부 서비스에 문장·입력을 보내지 않는다.

오디오 실패 검사는 후속 구현 단계에서 사용 권한이 있는 작은 테스트 파일로 수행한다. 이번 작업에는 파일 제작·구매·다운로드·음성 서비스 가입을 포함하지 않는다. 고의 실패 fixture의 재생 성공은 교육용 발음 또는 음성 배포 권리의 승인 근거가 아니다.

[ASSET-LICENSES.md](../content/ASSET-LICENSES.md)는 자산별 출처·권리 근거의 정본이다. 이 설계에 적힌 초안은 정식 등록된 제품 자산이 아니다. 한컴타자의 코드·화면·캐릭터·문항·음원과 제3자 문제집·노래·대사를 복제하지 않는다. 공개 자료를 도입할 때는 개별 자료와 매체의 조건을 다시 확인한다. 문서나 장부를 만들었다는 사실만으로 무침해를 확정하지 않는다.
