## 1. 검증 상태와 근거

문서·구조 검사는 제품의 실제 입력 동작, 브라우저 호환, 교육·번역 검수, 사용자 탐색과 구분한다. 아래는 **수용 기준의 정본**이며, 실행한 부분과 미실행 부분은 [I004](I004-harness-development.md) 및 개별 evidence에 기록한다. 코드·문서가 준비됐다는 사실만으로 수용 통과를 표시하지 않는다.

| 근거 종류 | 확인할 수 있는 것 | 대신할 수 없는 것 |
|---|---|---|
| 문서 검사 | 파일·링크·요구 추적·의존 관계·공백 오류 | 제품 기능·권리·학습 효과 |
| 순수 계산·합성 이벤트 | 정규화·산식·상태 전이·이벤트 중복 방어 | 실제 OS 조합·후보창·키 확정 |
| 브라우저 통합 | 화면·명시 동작·저장·오류·포커스 | 입력기를 거치지 않은 fill만으로 IME 동작 판단 |
| 실제 Windows 입력기 | 실제 키·조합·확정·취소·포커스 경계 | 다른 OS·입력기·브라우저 지원 보장 |
| 사람 콘텐츠 검수 | 특정 개정의 교육·번역·정답·권리 근거 | 구현·사용성·법률상 무침해 확정 |
| 소규모 사용자 탐색 | 과제 수행, 혼란, 도움 요청, 관찰된 회상 | 인과적 학습 효과나 전체 학습자 일반화 |

실행 기록에는 검사 ID, 티켓, 날짜, 실행자, 앱 소스 식별자, 콘텐츠 개정/묶음 버전, 채점 버전, OS·브라우저·입력기·키보드·보조기술 버전, 입력·행동, 예상·실제 결과, 근거 경로, 결함·재검증 여부를 남긴다. 원시 이벤트 로그는 정해진 개발 fixture에만 사용하며 학습자의 자유 입력을 수집하지 않는다. 결과는 `미실행 / 통과 / 실패 / 외부 의존으로 확인 불가`로 구분한다.

## 3. 실제 OS·브라우저 입력 환경표

첫 검증 범위는 Windows 11 PC의 Chrome·Edge다. 설치 버전과 키보드 배열은 실행 시 직접 기록하며 현재 지원이 확인됐다는 뜻은 아니다. 한글·Telex·VNI는 Microsoft Windows 입력기를 우선 검증한다. 영어 입력은 영문 배열의 일반 편집과 제출을 검증한다.

## 4. 입력·채점·중단의 구체 사례

아래 문자열은 기술 검증 fixture이며 승인된 교육 문항이 아니다. OS가 취소·삭제를 처리한 실제 문자열을 먼저 관찰하고 앱이 그 값을 보존하는지 검사한다. 특정 compositionend/input 순서를 맞췄다는 이유만으로 OS 검증을 완료하지 않는다.

| 사례 | 환경·입력/행동 | 예상 결과·기록 |

| V07-a 조합 표시 | E01/E02 두벌식에서 `r` → `k`를 눌러 `가`를 조합 | 화면 표시만 갱신. 중간 오답·정확도·제출·진도 0회 |
| V07-b Enter | 위 조합에서 Enter, 이어 입력란 Enter 반복·길게 누름 | IME 확정은 허용, 앱 제출·다음 문제 이동 0회 |

### V04/V16/V18 · 콘텐츠와 권리

- MH-005는 MH-C005·MH-C011·MH-C017 세 개 개념의 3언어 원문·해석·보기·정답·피드백·권리 근거를 검수한다. 개발 미리보기와 첫 흐름의 수용을 구분한다.
- MH-018은 MH-C001~MH-C020 전체 20개 개념과 60개 언어 변형을 확인한다. approved 표시뿐 아니라 실제 담당·날짜·개정·범위·근거가 있어야 한다.

- 자모 의미 과제는 null이고 단어·생활 문장·카페는 보기 3개와 정답 1개를 갖는다. 개념 ID 중복, 정답 ID 부재, 번역 누락, 잘못된 개정, 검수/권리 근거 누락 fixture를 검증기에 전달해 격리를 확인한다.
- 전부 격리되면 시작 대신 이용 가능한 문항이 없음을 안내한다. 진행 중 발견한 콘텐츠 오류는 오답·완료 분모에 넣지 않는다.
- [권리 장부](../content/ASSET-LICENSES.md)와 텍스트·이미지·음성 참조를 대조한다. 자체 작성·AI 생성·공개 자료라는 이유만으로 이용·배포 조건이 충족됐다고 판단하지 않는다.
- 문항 내용이 바뀌면 revision·영향 검수 상태가 바뀌고 이전 승인 근거가 현 개정으로 자동 승계되지 않는지 확인한다.

## 8. 소규모 사용자 탐색안 · MH-020 Backlog

대상 가정을 확인하기 위한 **제안 계획**이다. PC를 사용하는 베트남어 모어 성인 한국어 초급자 **5명**, 1명당 **20~30분**을 제안한다. 제품 안정화·최소 검수 콘텐츠·사용자 승인 후 모집/연락·설명/동의 절차를 준비한다. 이번 작업에서는 참여자 모집·연락·실험·분석 전송을 실행하지 않는다. 미성년자·개인별 민감정보를 추가 수집하는 범위는 포함하지 않는다.

| 순서 | 과제·측정 | 기록 |

| 다른 날 선택 후속 | 참여자가 동의한 경우에만 재사용 관찰 | 실제 간격·재사용 이유·도움 여부. 후속 연락도 별도 승인 범위 |

10분 지연은 각 문항의 마지막 의미 노출부터 계산한다. 진행이 길어져 시간 조건을 못 채우면 미측정으로 남긴다. 후속 재사용을 관찰하지 못한 경우 재방문 성공으로 기록하지 않는다.

사용성 목표 초안은 **5명 중 4명 이상이 진행자의 조작 도움 없이 첫 입력→의미→결과를 완료**, **4명 이상이 타자 결과와 의미 결과의 차이를 설명**, **미해결 입력 유실·중복 제출 0건**이다. 참가자 특성·실행 조건을 확인한 뒤 모집 전에 목표를 고정한다. 의미 정답률 상승이나 타자 속도 향상을 합격 목표로 미리 만들어 학습 효과를 주장하지 않는다.

해석을 본 의미 답과 숨김 회상을 분리하고 첫 답·재시도도 나눈다. 같은 문항을 다시 푼 결과에는 반복 노출·암기·입력 숙련·사전 지식이 영향을 준다. 5명 탐색의 관찰은 UI/콘텐츠 개선 근거이며 인과적 교육 효과 검증이나 베트남 학습자 전체에 대한 결론이 아니다.

## 9. 완료 판정과 결과 보존

- MH-001/002의 실제 입력기 근거 → MH-007/008 구현 검사 → MH-016 통합 실기 순서를 유지한다. 실제 OS 검사가 필요한 항목을 합성 이벤트 통과만으로 Done 처리하지 않는다.
- MH-019에서 V01~V04·V06~V19의 제품 결과, 8개 실기 환경, 9개 언어 조합, 전체 콘텐츠 검수와 결함 상태를 묶는다. V05는 문서·초기화 보존 결과로 별도 연결한다.
- 필수 검증 미실행·실패·외부 검수 미완료는 해당 게이트를 충족하지 않는다. 남은 결함·지원하지 못한 환경·오디오 미제공 상태를 명시한다.
- MH-020 사용자 탐색은 후속 평가다. 로컬 기술 MVP 수용을 학습 효과 입증이나 외부 공개 승인으로 표현하지 않는다.
- 현재 [baseline.json](../benchmarks/baseline.json)은 미측정 scaffold를 유지한다. 실제 측정 후에만 환경·산식·버전·근거와 함께 값을 기록한다. 문서 예시 수치는 baseline에 넣지 않는다.

현재 제품 테스트, 실제 IME 검사, 콘텐츠 검수, 사용자 탐색은 모두 **미실행**이다. 문서 검사 결과와 로컬 등록의 실제 상태는 [I002](I002-development-plan.md)에 별도 기록한다.
