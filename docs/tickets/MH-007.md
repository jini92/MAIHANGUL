# MH-007 · 확정 입력 제어와 문항 전환 보호

기준일: 2026-09-30 · 상태는 **착수 준비 상태**이며 이번 작업에서 구현·테스트를 실행한 것이 아니다.

## 목적과 사용자 변화

IME 조합과 페이지 조작이 겹쳐도 학습자의 입력을 안전하게 유지한다.

## 연결 요구사항·설계

R06, R07, R08, R17 · [요구사항](../A001-PRD.md) · [D003](../D003-input-scoring.md) · [D002](../D002-learning-game-ux.md) · [검증 계획](../T001-validation-plan.md): V06, V07, V08, V17

## 포함·제외 범위

InputController·epoch·시도 잠금·붙여넣기 표식. 점수 산식/진도 저장 제외.

## 선행 티켓과 착수 조건

- 선행: [MH-001](MH-001.md), [MH-002](MH-002.md), [MH-006](MH-006.md).
- 착수 조건: 선행 티켓의 수용 근거가 모두 연결되어야 Ready로 옮긴다. 아래 외부 의존도 별도로 충족한다.

## 구현 작업과 예상 변경 모듈

- 실기 로그에서 결정된 stable/composing/settling/submitted 상태를 구현한다.
- 명시 버튼 제출·동기 잠금·늦은 이벤트 폐기·재시도를 구현한다.
- UI 언어 유지/연습 언어 취소 확인과 마지막 확정값 재개를 연결한다.
- 예정 모듈/결과물: src/input 제어기·회귀 검사·입력 정책 근거.

## 수용 기준

1. 조합 중 입력·버튼 클릭은 채점 요청을 만들지 않고 안정화 후 새 버튼 행동만 한 번 전달한다.
2. 입력란 Enter/누른 채 반복/버튼 더블클릭으로 제출이 중복되지 않는다.
3. 다음 문제 전환 뒤 이전 input/end가 오면 새 입력값이 바뀌지 않는다.
4. UI 전환은 확정 입력을 유지하고 연습 언어 전환은 취소 확인 뒤 새 epoch를 만든다.

## 검증 방법과 실제 환경

실제 로그에서 도출한 합성 순서 재현 + Windows 두 브라우저 실제 IME 집중 검사. 합성만으로 OS 경계 수용 불가; 최종 통합은 MH-016.

## 결과물

src/input 제어기·회귀 검사·입력 정책 근거. 완료 시 실제 실행 명령/절차·버전·예상/실제·근거 링크·잔여 문제를 첨부한다.
