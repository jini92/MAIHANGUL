# MH-011 · 진도 저장·버전 이관·앱 데이터 삭제

기준일: 2026-09-30 · 상태는 **착수 준비 상태**이며 이번 작업에서 구현·테스트를 실행한 것이 아니다.

## 목적과 사용자 변화

로그인 없이 완료 진도를 보존하고 저장 실패와 삭제 범위를 알린다.

## 연결 요구사항·설계

R12, R15, R17 · [요구사항](../A001-PRD.md) · [D001](../D001-architecture-overview.md) · [검증 계획](../T001-validation-plan.md): V12, V15, V17

## 포함·제외 범위

단일 키 저장 어댑터·집계·버전·보존·다중 탭 안내·삭제. 클라우드·원시 입력 저장 제외.

## 선행 티켓과 착수 조건

- 선행: [MH-003](MH-003.md), [MH-006](MH-006.md).
- 착수 조건: 선행 티켓의 수용 근거가 모두 연결되어야 Ready로 옮긴다. 아래 외부 의존도 별도로 충족한다.

## 구현 작업과 예상 변경 모듈

- schemaVersion1 envelope와 contentVersion 매핑, 중복 attemptId 방지를 구현한다.
- 손상·구버전·미래버전·quota/보안 실패를 안전하게 처리한다.
- 90일/200개 보존과 학습기록 삭제/앱전체 삭제 두 범위를 구현한다.
- 예정 모듈/결과물: src/storage·src/progress 기본 저장, 실패/삭제 UI 및 근거.

## 수용 기준

1. 완료 결과를 저장 후 새로고침하면 진도가 유지되고 같은 attemptId를 다시 저장해도 완료 수는 늘지 않는다.
2. 손상/미래버전 값을 읽으면 경고와 메모리 모드로 시작하며 기존 값을 덮어쓰지 않는다.
3. 학습기록 삭제는 언어 설정을 유지하고, 앱전체 삭제는 앱 키만 제거하여 다른 테스트 키가 남는다.
4. 삭제 실패는 성공 표시가 없고 예약 쓰기가 삭제한 옛 데이터를 되살리지 않는다.
5. 최근 기록 201개/91일 자료는 보존 정책대로 정리하며 원시 입력은 저장되지 않는다.
6. 개별 completedAt으로 만료를 판정하고 scoringVersion 또는 contentVersion이 다른 결과는 이력·집계에서 구분한다. 첫 시도/재시도 표식은 저장·reload 후에도 유지된다.

## 검증 방법과 실제 환경

저장 어댑터 실패 주입·migration fixture·실제 브라우저 reload/다중 탭·다른 키 보존. 실제 사용자 데이터 대신 전용 로컬 origin fixture.

## 결과물

src/storage·src/progress 기본 저장, 실패/삭제 UI 및 근거. 완료 시 실제 실행 명령/절차·버전·예상/실제·근거 링크·잔여 문제를 첨부한다.

## 우선순위·크기·상태
