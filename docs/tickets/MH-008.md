# MH-008 · 문자 정확도·속도·의미 점수 계산

기준일: 2026-09-30 · 구현 결과와 정식 수용 상태는 아래 실행 결과를 구분해 읽는다.

## 목적과 사용자 변화

입력과 의미 성과를 정확하게 설명하고 다른 언어/환경의 기록을 혼합하지 않는다.

## 연결 요구사항·설계

R08, R09 · [요구사항](../A001-PRD.md) · [D003](../D003-input-scoring.md) · [검증 계획](../T001-validation-plan.md): V08, V09

## 포함·제외 범위

순수 정규화·군집 편집거리·CPM·첫 의미 선택·비교 자격. UI 완성/랭킹 제외.

## 선행 티켓과 착수 조건

- 선행: [MH-003](MH-003.md), [MH-006](MH-006.md).
- 착수 조건: 선행 티켓의 수용 근거가 모두 연결되어야 Ready로 옮긴다. 아래 외부 의존도 별도로 충족한다.

## 구현 작업과 예상 변경 모듈

- strict-nfc-v1·scoring-v1을 구현하고 D003 수식을 fixture로 검사한다.
- 시계·입력 방식·힌트·붙여넣기·중단·첫 시도를 분리 저장할 결과 타입을 만든다.
- 정답 boolean과 반올림 표시를 분리한다.
- 예정 모듈/결과물: src/scoring 함수/타입과 산식 사례 검사.

## 수용 기준

1. ‘한글’/‘한굴’, 4초를 주면 정확도 50.0%, CPM 30, 정답 false다.
2. ‘xin chào’/‘xin chao’,16초를 주면 87.5%,30이고 성조 차이를 오답으로 남긴다.
3. 빈 제출은 점수 없음, t≤0은 속도 null, 붙여넣기/중단은 비교 제외다.
4. 입력란에서 제출 버튼으로 Tab 이동한 정상 제출은 속도 비교에서 제외되지 않는다.
5. 의미 첫 오답 후 재시도 정답은 첫 의미 점수의 정답 수를 늘리지 않는다.

## 검증 방법과 실제 환경

단위 검사로 정확·삽입·삭제·NFC·공백·구두점·대소문자·반올림·t 경계를 확인. 실제 입력기는 MH-016.

## 결과물

src/scoring 함수/타입과 산식 사례 검사. 완료 시 실제 실행 명령/절차·버전·예상/실제·근거 링크·잔여 문제를 첨부한다.

## 우선순위·크기·상태

P0 · S · Blocked. 크기는 [INDEX](INDEX.md)의 상대 추정이며 외부 대기 시간은 포함하지 않는다.

## 미확정 사항·외부 의존

다른 scoringVersion끼리 비교하지 않음. 미지원 군집 분할 환경은 표시/지원 판단 필요.
