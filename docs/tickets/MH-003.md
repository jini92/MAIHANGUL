# MH-003 · 문항 스키마와 검수 상태 검증기

기준일: 2026-09-30 · 구현 결과와 정식 수용 상태는 아래 실행 결과를 구분해 읽는다.

## 목적과 사용자 변화

번역·정답·권리 정보가 불완전한 문항을 학습 목록에 넣지 않는다.

## 연결 요구사항·설계

R02, R04, R16, R18 · [요구사항](../A001-PRD.md) · [D004](../D004-content-data-rights.md) · [D001](../D001-architecture-overview.md) · [검증 계획](../T001-validation-plan.md): V02, V04, V16, V18

## 포함·제외 범위

문서 스키마를 로컬 JSON schema/검증기로 옮기기와 작은 개발 fixture. 실제 20문항 작성·번역 검수 제외.

## 선행 티켓과 착수 조건

- 선행: 없음.
- 착수 조건: 문서 계약이 준비되어 독립 착수 가능하다. 환경 확인·최소 도구 준비를 포함한다. 실기나 외부 검수의 완료 조건은 생략할 수 없다.

## 구현 작업과 예상 변경 모듈

- 개념 ID/revision, 3개 변형, 해석·보기·정답·권리·검수 필드를 검증한다.
- 개념과 저장 필드의 버전 매핑을 명시하고 release/preview 로딩 경계를 만든다.
- HTML 문자열은 텍스트로 취급하고 누락/중복/잘못된 정답을 진단한다.
- 예정 모듈/결과물: 콘텐츠 스키마·검증기·의미 있는 오류 fixture 및 docs/evidence/MH-003-schema.md.

## 수용 기준

1. vi 해석이 빠진 fixture를 넣으면 누락 경로를 반환하고 학습 목록에서 제외한다.
2. 중복 ID, 정답 보기 없음/복수 정답, 권리 보류를 넣으면 각각 검사 실패다.
3. 정상 구조지만 draft인 문항은 개발 preview에서만 로드되고 release 목록에는 없다.
4. 서로 다른 개념 revision과 저장 revision을 혼동하지 않고 버전을 보존한다.

## 검증 방법과 실제 환경

로컬 JSON/스키마 구조 검사와 정상·누락·오염 fixture. 외부 서비스·실제 IME 없이 착수 가능.

## 결과물

콘텐츠 스키마·검증기·의미 있는 오류 fixture 및 docs/evidence/MH-003-schema.md. 완료 시 실제 실행 명령/절차·버전·예상/실제·근거 링크·잔여 문제를 첨부한다.

## 우선순위·크기·상태

P0 · S · Done. 크기는 [INDEX](INDEX.md)의 상대 추정이며 외부 대기 시간은 포함하지 않는다.

## 미확정 사항·외부 의존

최종 검수 담당 미정이지만 구조 검증 작업에는 영향 없음.

## 실행 결과

스키마·검수 개정·권리 참조·preview/release 검증기를 구현했다. 독립 검수 RD-01 수정 후 재현 검사로 수용했다. 전문가 콘텐츠 승인은 이 티켓의 범위 밖이다.

근거: [하네스 실행·통합 검증](../I004-harness-development.md) · [개별 근거](../evidence/MH-003-schema.md)
