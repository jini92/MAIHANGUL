# MH-002 · Telex·VNI와 NFC 문자 단위 실험

기준일: 2026-09-30 · 상태는 **착수 준비 상태**이며 이번 작업에서 구현·테스트를 실행한 것이 아니다.

## 목적과 사용자 변화

베트남어 성조가 입력·수정·채점 과정에서 사라지지 않는지 먼저 확인한다.

## 연결 요구사항·설계

R02, R08, R09 · [요구사항](../A001-PRD.md) · [D003](../D003-input-scoring.md) · [검증 계획](../T001-validation-plan.md): V02, V08, V09

## 포함·제외 범위

로컬 최소 프로브, Telex/VNI 두 입력 방식, 영문 입력, NFC/군집 분할. 입력기 개발·전체 교육과정 제외.

## 선행 티켓과 착수 조건

- 선행: 없음.
- 착수 조건: 문서 계약이 준비되어 독립 착수 가능하다. 환경 확인·최소 도구 준비를 포함한다. 실기나 외부 검수의 완료 조건은 생략할 수 없다.

## 구현 작업과 예상 변경 모듈

- 실제 Windows Telex/VNI의 설치와 활성화 상태를 확인하고 고정 fixture 절차를 준비한다.
- ‘chào’·성조 수정·삭제·포커스 이동의 실제 문자열/이벤트를 두 브라우저에서 기록한다.
- NFC 동등성 및 Intl.Segmenter 군집 수를 D003 사례와 대조한다.
- 예정 모듈/결과물: docs/evidence/MH-002-vietnamese.md, 고정 문자 fixture와 관찰 로그(후속 개발 산출물).

## 수용 기준

1. Telex와 VNI로 각각 ‘chào’를 입력하면 성조가 보존되고 ‘chao’와는 다른 값이다.
2. ‘cha\u0300o’와 ‘chào’는 NFC 후 같으며 군집 수가 같다. 서로 다른 성조는 같게 처리하지 않는다.
3. 영문 ‘cat’/‘Cat’, 내부 공백, 붙여넣기를 관찰하여 D003 정책을 적용할 수 있는 근거를 남긴다.
4. Telex/VNI × Chrome/Edge 실제 로그가 없으면 완료가 아니다.

## 검증 방법과 실제 환경

실제 Windows Telex/VNI, 영문 키보드, Chrome·Edge. OS 입력기의 실제 전환·타이핑은 현지 조작자가 필요하다. 브라우저 fill/문자열 대입은 실제 IME 근거로 사용하지 않는다.

## 결과물

docs/evidence/MH-002-vietnamese.md, 고정 문자 fixture와 관찰 로그(후속 개발 산출물). 완료 시 실제 실행 명령/절차·버전·예상/실제·근거 링크·잔여 문제를 첨부한다.
