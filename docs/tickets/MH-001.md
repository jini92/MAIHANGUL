# MH-001 · 한글 IME 이벤트 순서와 제출 경계 실험

기준일: 2026-09-30 · 구현 결과와 정식 수용 상태는 아래 실행 결과를 구분해 읽는다.

## 목적과 사용자 변화

한글을 조합하는 동안 오답이나 중복 제출이 생기는 위험을 구현 전에 확인한다.

## 연결 요구사항·설계

R07, R17 · [요구사항](../A001-PRD.md) · [D003](../D003-input-scoring.md) · [검증 계획](../T001-validation-plan.md): V07, V17

## 포함·제외 범위

프레임워크 없는 로컬 이벤트 관찰 페이지와 정해진 fixture, Windows 실기 로그. 제품 화면·배포·일반 사용자 키 입력 수집은 제외.

## 선행 티켓과 착수 조건

- 선행: 없음.
- 착수 조건: 문서 계약이 준비되어 독립 착수 가능하다. 환경 확인·최소 도구 준비를 포함한다. 실기나 외부 검수의 완료 조건은 생략할 수 없다.

## 구현 작업과 예상 변경 모듈

- 로컬 프로브에서 composition/beforeinput/input/key/focus 이벤트와 DOM 값·시각·epoch를 기록한다.
- 한글 두벌식의 확정·취소·Backspace·선택 교체·Tab/클릭·문제 전환을 Chrome/Edge에서 관찰한다.
- D003 settling 종료와 버튼 제출 잠금 후보를 비교하고 근거로 갱신한다.
- 예정 모듈/결과물: 로컬 probe, docs/evidence/MH-001-ime.md 및 정해진 fixture 이벤트 로그(개발 시 생성).

## 수용 기준

1. ‘ㅎ→하→한’ 조합을 수행하면 중간 채점/제출 카운터는 0이고 확정 문자열은 ‘한’이다.
2. 조합 중 Enter를 누르면 IME만 확정되고 앱 제출은 0회다. 안정화 후 버튼을 새로 활성화하면 1회다.
3. 조합 중 다음 문제를 요청한 후 늦은 compositionend/input이 오면 새 epoch의 입력·점수는 변하지 않는다.
4. Chrome·Edge별 실제 로그와 실패/미실행을 기록한다. 합성 이벤트만 있으면 완료로 표시하지 않는다.

## 검증 방법과 실제 환경

Windows PC·실제 한국어 IME·Chrome/Edge·물리 키보드와 현지 조작자가 필요하다. 먼저 OS/브라우저/입력기 설치·버전을 확인하고 정해진 문구만 기록한다. 합성 테스트는 보조다.

## 결과물

로컬 probe, docs/evidence/MH-001-ime.md 및 정해진 fixture 이벤트 로그(개발 시 생성). 완료 시 실제 실행 명령/절차·버전·예상/실제·근거 링크·잔여 문제를 첨부한다.

## 우선순위·크기·상태

P0 · S · Blocked. 크기는 [INDEX](INDEX.md)의 상대 추정이며 외부 대기 시간은 포함하지 않는다.

## 미확정 사항·외부 의존

현재 실기 미실행. 실제 조작 수단/입력기 부재 시 준비만 수행하고 실행 부분은 Blocked로 전환한다. 설치·계정 변경을 자동 수행하지 않는다.

## 실행 결과

관찰 프로브·입력 합성 검사를 구현했다. 실제 Windows 두벌식 조작 로그 확보 대기다.

근거: [하네스 실행·통합 검증](../I004-harness-development.md) · [개별 근거](../evidence/MH-001-ime.md)

로컬 구현/수용 상태이며 GitHub 이슈의 원격 완료 여부와 구분한다. 실제 환경·외부 검수 조건은 자동 검사로 면제하지 않는다.
